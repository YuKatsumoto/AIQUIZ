# オフライン問題 大量補充 作問仕様

目標は「数」ではなく、**小学生が遊んで楽しく、解いて賢くなり、先生が見ても誤りがない問題**。
200問のうち1問でも誤答・曖昧な問題があれば、そのファイル全体の信用が落ちる。迷ったら作らない。

`AIQUIZ-Godot/offline_bank.json` は直接編集せず、**シャードファイル**に書き、
`validate.py` と独立レビュー（`REVIEW.md`）を通してから push する。本体への統合は `merge.py` で別途行う。

## 1. 出力ファイル

`AIQUIZ-Godot/tools/quiz_expansion/shards/<slug>_g<学年>_<batch>.json`

| 教科 | slug |
|---|---|
| 算数 | math |
| 理科 | science |
| 国語 | japanese |
| 社会 | social |
| 英語 | english |

```json
{
  "subject": "理科",
  "grade": 5,
  "batch": "b",
  "items": [
    {"q": "問題文", "c": ["選択肢1", "選択肢2", "選択肢3", "選択肢4"], "a": 2,
     "exp": "解説", "t": 4.0, "g": "単元名"}
  ]
}
```

- `q` 問題文（90字以内）
- `c` 選択肢ちょうど4つ（各30字以内、重複なし）
- `a` 正解のインデックス 0〜3
- `exp` 解説（15〜120字）。§2.4 を満たすこと
- `t` 想定解答秒数 1.5〜10.0（§2.6）
- `g` 単元名（12字以内）。同じ単元は同じ表記で統一する（ゲームは同じ単元の連続出題を抑える）

## 2. 品質基準（いちばん大事）

### 2.1 正解は「ただ1つ」で「誰が見ても」正しい
- 教科書（主要各社に共通する内容）と学習指導要領の範囲で、**確定した事実**だけを問う。
- 正解が条件次第で変わる問題は禁止: 「〜が多い」「いちばん〜」は比較の範囲が明確なときだけ。
  地域・家庭・季節・年度・教科書会社で答えが変わるもの、統計の順位や最新値、現職の人物は出さない。
- 誤答の3つは「**それっぽいが、根拠をもって明確に誤り**」。「ある意味では正しい」と言える選択肢を1つでも残さない。
- 「すべて正しい」「どれでもない」は禁止。「正しくないものはどれ」形式は可（問題文で「正しくないもの」を明示）。

### 2.2 誤答（ディストラクター）は「よくあるまちがい」から作る
誤答は、**その学年の子が実際にやりがちな誤り**を表すように作る。これが良問と凡問の最大の差。
- 算数: 繰り上がり忘れ、位取りのずれ、公式の取り違え（三角形で÷2を忘れる、円周と面積の混同）、単位換算の桁ずれ、
  割合で「もとにする量」を取り違えた値。誤答はすべて、ある誤った考え方から実際に出てくる数にする。
- 理科: 素朴概念（重い物ほど速く落ちる、植物は土から養分を食べる）、似た用語（蒸発/ふっとう、受粉/受精）、条件の取り違え。
- 国語: 形の似た漢字、同音異義語、意味の近い慣用句、送りがなのゆれ、音読み訓読みの取り違え。
- 社会: 同時代・同分野の別の人物や出来事、隣接する県や地域、似た制度（衆議院/参議院）。
- 英語: つづりの似た語、同じカテゴリーの別の語（曜日・月・教科）、日本語発音につられた誤り。

**禁止**: 冗談や明らかに場違いな誤答（「まくら」「大きな声を出す」「空をとぶ」など）、他の3つとカテゴリーが違う誤答。
4つは同じカテゴリー・同じ品詞・同じ単位・ほぼ同じ長さと具体性にそろえる。
**正解だけ長い・具体的・丁寧**にしない（子どもは「迷ったら長いの」で当ててしまう）。正解が最も長い選択肢になるのは全体の25%前後に。

### 2.3 問題文は短く、一度読めば分かる
- 何を答えるのかが文末で明確（「〜はどれですか？」「〜は何ですか？」）。
- 二重否定や紛らわしい否定を使わない。否定で問うときは「正しくないもの」と明示。
- 問題文に答えのヒント（正解の語そのもの、正解とだけ一致する語尾など）を入れない。
- 図・表・写真を前提にしない。ゲーム画面では文字しか出ない。
- 同じ型の問い方（例「『X』の意味はどれですか？」）がファイル全体の8%を超えないよう、問い方を変える:
  一問一答 / 理由を問う / 結果を予想する / 順番に並べる / 仲間はずれ / 正しくないもの / 例文の中での使い方 /
  具体的な場面に当てはめる / 計算・数量 / 原因と結果。

### 2.4 解説は「なるほど」と思える1〜2文
- 正解の理由を必ず書く。主な誤答がなぜ違うかを一言添えると良い。
- 「XはYです。」だけの言い直しは不可。覚え方、身近な例、豆知識のどれかを加える。
  - 悪い例: `runは「走る」です。`
  - 良い例: `runは「走る」。I can run fast. のように使います。walk（歩く）とまちがえないように。`

### 2.5 学年に合った言葉と漢字
- その学年までに習う内容だけを出す。上の学年の内容は出さない。
- 漢字は学年別漢字配当表で**その学年までに習う漢字**だけ。それ以外はひらがなにする（`漢字（よみ）` 形式のふりがなは使わない）。
- 1・2年はひらがな中心で短く。必要なら文節の間に半角スペースを入れてよい。

### 2.6 難しさを散らし、`t` を正しく見積もる
- 一発で分かる知識問題・少し考える問題・複数ステップの思考や応用が必要な問題を **約1/3ずつ**。
  ゲームは問題文の長さや思考量で「簡単/普通/難しい」に3分割するので、全部同じ難しさにしない。
- 「難しい」側（`t` 6.5秒以上）を**必ず3割以上**。例: 出来事の順番・理由・比較、条件を変えた実験の結果予想、
  2段階以上の計算、正しくないものを選ぶ問題、例文の中での使い分け、具体的な場面への当てはめ。
- `t` = 読む時間（低学年は1秒あたり約5字、高学年は約8字） + 考える時間（知識1〜2秒、計算や推論3〜6秒）。

### 2.7 楽しさと学び
- 子どもが「へえ」と思う事実、身近な場面（給食、遊び、家、町、季節の行事）を使う。
- 丸暗記の確認だけでなく、**理解しているか**を確かめる問いを混ぜる。
- 同じ知識を何度も問わない。1つの単元の中でも問う知識と切り口を変える。

### 2.8 良い例・悪い例
- 悪い: `学校で困ったときに助けてくれる人はだれ？ | 先生/お友達/お父さん/お母さん` → 正解が1つに決まらない。
- 悪い: `だんごむしは、びっくりするとどうなる？ | 丸くなる/空をとぶ/色がかわる/大きな声をだす` → 誤答が冗談で、考えなくても分かる。
- 良い: `ふりこの1往復の時間を長くするには、どうすればよいですか？ | おもりを重くする/ふれはばを大きくする/ふりこの長さを長くする/おもりを軽くする`
  → 誤答はどれも子どもが実際に考えがちな条件で、実験で学んだ「長さだけが関係する」を理解しているか確かめられる。
- 良い: `36 × 25 を計算すると？ | 900/720/180/9000` → 720（36×20）と180（36×5）は途中の部分積、9000は位取りの誤り。

## 3. 教科・学年の注意
- 理科・社会は3〜6年、英語は3〜6年だけ。理科・社会の1・2年（学校では生活科）はゲームで選べないので作らない（validate.py がエラーにする）。
- 英語: 小学校外国語の語彙・表現の範囲。4択は全部英語か全部日本語にそろえる。
- 算数: 全問を検算する。文章題を3割以上。

## 4. 重複禁止
- 作り始める前に、担当教科・担当学年の既存問題（本体とシャード）を一覧で**全部読み**、どの単元がどの切り口で出ているかを把握する:
  `python AIQUIZ-Godot/tools/quiz_expansion/list_existing.py <教科> <学年>`
  `offline_bank.json` やシャードの JSON を丸ごと読まない（トークンの無駄）。前後の学年との重複は validate.py が検出する。
- 既存問題と同じ問題・言い換えだけの問題は禁止。同じ単元でも、問う知識や切り口を変える。
- `validate.py` は完全一致をエラー、類似（類似度0.85以上）を警告で出す。

## 5. 手順

1. 既存問題を読む → その学年の主要単元を**8〜15個**挙げ、単元ごとの目標数と、各単元で問う知識の一覧を作る（同じ知識を2回問わない計画）。
2. 50問くらいずつシャードに書き足す。書きながら §2 を1問ずつ満たしているか確認する。
3. **自己チェック**: 全問を作問者の目でもう一度見直し、§2 のどれかに引っかかる問題は直すか作り直す。
4. 検証:
   ```
   python AIQUIZ-Godot/tools/quiz_expansion/validate.py AIQUIZ-Godot/tools/quiz_expansion/shards/<file>.json
   ```
   エラー0件になるまで直す。警告も原則すべて解消する。
   ただし「answer ... appears in the question」は、例文の一部（主語・修飾語・指示語の指す内容など）を選ばせる問題では正常なので無視してよい。
5. **独立レビュー**: `REVIEW.md` の手順で、作問者とは別のレビュアー（新しいサブエージェント）が答えを見ずに全問を解き、
   問題点を洗い出す。指摘をすべて直し、もう一度 validate を通す。
6. 自分のシャードファイルだけをコミットして push する（`offline_bank.json` やほかのファイルは変更しない）。
   ORCHESTRATOR.md のオーケストレーターから呼ばれたサブエージェントは commit/push せず、ファイルを書くだけにする。
