# 独立レビュー手順（ブラインド解答）

作問者は自分の問題の曖昧さに気づきにくい。そこで**作問に関わっていない新しいレビュアー**が、
正解キーを見ずに全問を解き、`SPEC.md` §2 の基準で厳しく審査する。
レビュアーの役目は「通すこと」ではなく「**子どもや先生から苦情が来る問題を1問残らず見つけること**」。

## 手順

1. `AIQUIZ-Godot/tools/quiz_expansion/SPEC.md` の §2 を読む。シャードファイル本体（正解・解説入り）は**まだ開かない**。
2. 正解を伏せた問題を表示する（50問ずつ）:
   ```
   python AIQUIZ-Godot/tools/quiz_expansion/blind_review.py show <shard.json> 0 50
   ```
3. 1問ずつ、その学年の子どもになったつもりで、また教科の先生のつもりで解く。各問について:
   - 自分の答え（0〜3）。**正解として弁護できる選択肢が2つ以上ある、または1つもない場合は null**。
   - 気になった点があればメモ（下のチェックリストの番号）。
4. 回答を JSON に保存して突き合わせる（`{"0": 2, "1": 0, "2": null, ...}`）:
   ```
   python AIQUIZ-Godot/tools/quiz_expansion/blind_review.py check <shard.json> <answers.json>
   ```
5. ここで初めてシャード本体を開き、不一致・null・メモのついた問題と、全問の解説を審査する。
6. 指摘リストを作る。各指摘は `#番号 / チェック番号 / 何が問題か / 具体的な直し方`。
   作問者（またはオーケストレーター）が全部直したあと、直した問題だけをもう一度ブラインドで解いて確認する。

## チェックリスト

1. **正解が誤り**、または事実関係があやしい（数値、年号、用語、つづり、読み）。
2. **正解が複数ある**／ある条件下では誤答も正しいと言える／正解が1つもない。
3. 学年外の内容・漢字・語彙が入っている。
4. 問題文が曖昧、二通りに読める、何を答えるか分かりにくい。
5. 誤答が冗談・場違い・カテゴリー違いで、考えずに消去できる。
6. 正解だけ長い・具体的・言い回しが違うなど、知らなくても当てられる手がかりがある。
7. 問題文に答えのヒントがある。
8. 解説が正解の理由になっていない、言い直しだけ、または誤り。
9. 図や表がないと解けない、地域・家庭・年度で答えが変わる。
10. 既存問題やほかの問題とほぼ同じ／同じ知識の焼き直し。
11. `t` が明らかに不適切（読むだけで時間切れ、または長すぎ）。
12. 退屈・機械的すぎる（同じ型の連続、学びのない一問一答の羅列）。

## 判定の目安

- ブラインド解答の不一致や null は、**ほぼ必ず問題に欠陥がある**とみなす。「自分の読み違い」で片づけず、
  子どもが同じ読み違いをしないかを考え、問題文か選択肢を直す。
- チェック1・2・9に当たる問題は、直せなければ削除して別の問題に差し替える。
- 不一致・削除がファイルの5%を超えたら、そのファイルの全問を作問者がもう一度見直す。

## レビュアーの報告

- 解いた問題数、不一致数、null 数
- チェック番号ごとの指摘数と、主な指摘の例
- 直した・差し替えた問題の番号
- 再確認（直した問題のブラインド再解答）の結果
