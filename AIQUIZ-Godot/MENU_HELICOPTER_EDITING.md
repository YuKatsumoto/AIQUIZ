# メインメニューのヘリアニメーション編集

Godotで `res://scenes/menu_helicopter_sequence.tscn` を開きます。既定の `start_pickup` がスタート時の回収です。

## 飛行経路

- `PickupP1Path` / `PickupP2Path`: スタート時の接近・ホバー・キャラクターを吊ったままの前進と上昇・退出。
- カーブは4点です。点0=進入、点1=ホバー、点2=前方7.8m・上方2.2mの位置、点3=退出。
- 3Dビューで点とハンドルを動かせます。進行距離のキーは滑らかな加減速曲線です。スタート用トラックの時間を従来の65%に短縮しています。
- 実ゲームの回収地点は固定です。1Pは `(-1.5, -1.2, -4.0)`、2Pは左 `(-8, -1.2, -4.0)`・右 `(4, -1.2, -4.0)`。機体のホバー高度はY=9mです。2Pの地点間隔は12mです。カメラ側へ寄せて、走行距離を短くしています。
- シーンのルートにある `Fixed ground pickup positions` で固定地点を調整できます。実行時はカーブの点1をその地点の上空へ合わせます。キャラ位置に合わせた経路の平行移動は行いません。
- 2Pは開始時に左にいるキャラが左地点、右にいるキャラが右地点へ走ります。各キャラ・担当ヘリの色は維持し、走行経路が交差する左右入れ替えを避けます。助走距離は開始位置によって変わります。
- `IntroP1Path` / `IntroP2Path` と `intro_arrival` は既存のメニュー投下用です。

## スタート時の流れ

UIは3つの手順表示を左右のシャッターで覆い（0.14秒）、`LETS'GO` を2回点滅（0.20秒）、メニューを下へ退場（0.22秒）させます。設定時間の合計は0.56秒。その後ヘリ回収が始まります。

1. キャラクターは両足をついて待ち、ヘリが固定地点へ接近してロープを降ろします。回収通路を塞ぐ壁だけは0.35秒で床下へ下げ、走行前に通路を空けます。中断時は壁を復元します。
2. ロープが全長の95%以上まで伸びたことを物理状態から確認し、そのキャラクターが走り始めます。
3. ロープの手前まで助走し、最後の一歩で止まらず、0.62秒の前方ジャンプ・つかまり動作へつなぎます。助走は最高8.0m/s、踏み切り地点は回収位置の最大1.45m手前です。膝を曲げた跳躍から両手を伸ばします。
4. 全員がロープをつかんだ次の更新で、担当ヘリがそろって前進・上昇を始めます。2人時は先に着いた側がホバーしたまま待ち、両方つかんでから出発します。
5. ロープは約7.28mの長さを保ちます。巻き上げ・機内への搭乗は行いません。ロープが出るハッチも開いたままです。
6. 全員のつかまりと退出の進行を確認してから黒ワイプを開始します。覆われるまでロープとキャラクターの表示を保ちます。

`start_pickup` の経路トラックは5.1675秒。P2は基本0.104秒遅れます。経路の時刻はプレイヤーごとに管理し、全員がつかむまでP1は2.3075秒、P2は2.4115秒で保持するため、実時間にはその待機が加わります。発進速度は約6.15m/sで、退出まで減速せず加速します。黒ワイプの判定には遅い側の経路時刻を使います。走る距離も開始時のキャラクター位置によって変わります。メニュー側の待機上限は12秒です。

主なトラックは `progress_ratio`、`p1/p2_hatch`、`p1/p2_ladder_deploy`、`p1/p2_action_progress`、カメラFOV・仰角です。`action_progress`は開始要求で、実際のジャンプはロープが降り、走り終わった時点から始まります。接近・つかまり・経路にそれぞれの時刻を使い、途中の姿勢への瞬間移動を防ぎます。

実ゲームの機体姿勢は `helicopter_arrival_director.gd::_set_flight_transform()` が移動の加速度、重力、空気抵抗補正から求めます。ピッチを経路の上向き角度へ直接合わせず、ヨーと姿勢変化には速度制限と応答遅れを設けています。これは演出用の物理特性を反映したアニメーションで、空力を網羅する飛行シミュレーターではありません。`bank_deg` / `pitch_deg` は小さな補正として使います。

ロープは `physical_rope_ladder.gd` が重力・慣性と長さの拘束を計算します。メニュー出発では下向きの放出速度を9.5m/sにし、展開中の減衰と伸び切った際の跳ね返りを弱めて、降下を速めています。ステージ到着は既定の物理設定を使います。手のIKを背骨の揺れの後に解き、吊り下がったままの飛行中も両手が段に追従します。

実ゲームの出発カメラは、構図補正を追加する前の動作に復元しました。回収位置へ寄せる移動と向きの自動補正を削除し、元の位置・向きを基準に、既存のFOV・仰角トラックと微振動だけを適用します。

F6はカーブ形状の参照プレビューです。実ゲームでは上記の固定地点へ経路を配置します。ロープが降りてからの走行、実キャラクターのジャンプと手、UIとワイプの順序はF5の実ゲームで確認してください。

2026-09-11の固定地点版をForward+で実行し、1P・2Pの回収・退出を確認しました。ロープ展開完了はP1=約2.38〜2.45秒、P2=約2.53〜2.65秒。位置を変えた2P実行でもホバー地点は同じ左右2か所となり、ローターを含む機体AABBの最小間隔は約1.82m、ロープ下端同士は約11.5m以上でした。回収中の機体とロープが画面内に収まり、元のカメラ動作も維持しています。助走距離により演出時間は変わります（測定例1P=7.49秒）。UI退場とステージ読み込みは含みません。

1P・2Pとも、ロープ展開後の助走、初回進捗0%からの前方ジャンプ、画面内のつかまり、全員つかまり後の次更新での発進、退出中の速度低下なし、巻き上げ量0、ロープ長7.28mを確認しました。全員がぶら下がったまま退出し、ステージへ遷移しました。

## ステージ到着

接近経路を28mから18mへ短縮し、ホバー待機とハッチ開放を重ね、繰り返しの大振りを一度の小さな振りへ変更しています。キャラクターの下降、ジャンプ、着地、ローターの再生速度は変更していません。着地と復帰が完了した時点でスタート入力を解放し、ヘリの退出は継続します。

2026-09-10のForward+実行で、演出開始からスタート入力解放まで1P=9.23秒、2P=9.54秒。変更前の2Pは約13.15秒でした。シーン読み込み・問題準備の時間はこの値に含めません。
