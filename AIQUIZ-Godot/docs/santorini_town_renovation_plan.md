サントリーニ風の街並みへの大規模改修計画

2026-09-13作成。対象は C:/AIQUIZ/AIQUIZ-Godot のメニュー・本編で共用している街。今回は調査と計画を行い、街のモデル、ゲームスクリプト、Godotのシーン・リソースは変更していない。

目指すのは、**海から立ち上がる崖と段丘に白い家々が重なり、青いドーム・建具・テラスが見える、明るいサントリーニ風の港町**。リンク先の建築表現を参考にし、地形と街区配置はAIQUIZのカメラとコースに合わせて設計する。

参照した[MeshworksのSantoriniキット](https://assetstore.unity.com/packages/3d/environments/fantasy/santorini-modular-stylized-greek-island-town-kit-340718)では、白い壁、青いドームと窓枠、アーチ、階段、石畳、パーゴラ、花・植栽、小さな広場を確認した。表紙とギャラリー9枚目を目視し、商品説明も確認済み。段丘と崖を組み合わせる方針は、本プロジェクト向けの提案である。

現在の実装は[harbor_city_backdrop.gd](/C:/AIQUIZ/AIQUIZ-Godot/scripts/world/harbor_city_backdrop.gd)からGLBを配置し、StageEnvironmentを通じてメニューと本編で共用している。現在の制作記録は368棟・23街区、約349,718三角形、13統合メッシュ・137マテリアル面。左右の内側岸壁はコース軸から約1,220m離れている。

今回確認した実行中のメニューでは、平らな岸壁に高層の建物が並び、水平線付近の細い帯として見えている。[保存済みの2人プレイ画像](/C:/AIQUIZ/AIQUIZ-Godot/artifacts/harbor_city/gameplay_2p_day.png)では、観客席が左右の遠景を大きく遮っている。今回、本編のプレイ遷移・性能測定は再実行していない。この視認性を最初の設計課題にする。

| 改修対象 | 提案する姿 | 制作上の要点 |
| --- | --- | --- |
| 地形・海岸 | 自然に曲がる湾、岩の崖、段々の宅地、小さな港 | 海岸から丘上まで地形をつなぎ、家と階段を接地させる |
| 建物 | 主に1～3階の白い家、丸みのある角、陸屋根・ヴォールト屋根 | 高低差は地形と建物の重なりで作る。各戸の幅・向き・屋上形状を変える |
| 街の目印 | 青いドームの教会、鐘楼、岬の風車 | 主要視点から見える位置に少数配置し、地区ごとに異なる輪郭を作る |
| 路地・広場 | 曲がる階段、石畳、連続する白い塀、見晴らしのよいテラス | 港→住宅地→教会広場のつながりが俯瞰でも理解できるようにする |
| 色・素材 | 少し暖かい白、深い青、落ち着いた石の色、緑、少量のピンクの花 | 白飛びを避け、白壁の陰影を残す。青はドーム・扉・窓・手すりに配分 |
| 生活感 | 木陰の席、鉢植え、ブーゲンビリア、街灯、日除け | 画面で判別できる場所を優先し、遠い地区では形と色のまとまりに集約 |

街は既存の三方向の配置を出発点にし、**後方は教会と密集した白い集落、左は岩の崖と段丘住宅、右は港・テラス・岬の風車**を主題にする。メニューでは後方の集落が背景の主役になり、ヘリの移動では湾全体のつながりが分かる構成を目指す。

通常プレイでは、観客席の奥や上に白い家のまとまりと青いドームが見える構図を設計する。進行方向中央は長いコースと飛行経路のために開け、左右の岬の位置・高さで街の存在感を出す。メニューと本編は同じ配置を共用し、移動演出の途中で街の位置が変わらないようにする。

現行の約1.2kmという距離で小さな建具や路地まで読み取ることは難しい。**距離・標高・街区の大きさの見直しを改修範囲に含め、実際のカメラから決める**。最終座標と棟数は、この構図検証が済んでから確定する。現在のカメラから街側の配置を先に調整し、問題文・回答・キャラクターの見やすさを合格条件にする。

| 順序 | 作業 | 提示する成果・次へ進む条件 |
| --- | --- | --- |
| 1 | 現状の基準を保存し、簡単な地形と白い建物で構図を比較する | 低めの段丘案と崖を強調した案を同じメニュー・1P・2Pカメラで比較。観客席越しに街を認識でき、出題表示を遮らない案を選ぶ |
| 2 | 代表街区を1つ仕上げる | 18～24棟程度、青いドーム1基、階段、広場、港、花のあるテラスを制作。同じ街区の実ゲーム画面と寄りの確認画像で、形・密度・白と青のバランスを判断する |
| 3 | 共通の建築部品と地形を整える | 家の基本形6～8種、壁・屋根・アーチ・階段・手すり等25～35部品程度を初期目安にする。地面と路地の接続、部品の寸法、素材を揃える |
| 4 | 左・後方・右へ街を展開する | 目安250～400棟の規模から画面上の密度で調整。教会・港・風車を各地区の核とし、海岸線・標高・路地・屋上を変えて街全体を作る |
| 5 | Godotへ統合し、昼・夕方・夜の見え方を整える | 共通の街シーン、既存の昼夜への連動、編集可能な街区配置を確認。白壁の陰影と夜の暖かい窓・街灯のバランスを実行画面で調整する |
| 6 | 描画負荷とゲーム内の一連の動作を検証する | 画質別の性能比較、メニュー→ヘリ出発→ゲーム到着→通常プレイ→リトライ→メニュー復帰の画像と記録を残す |

数量は計画上の目安。代表街区の見た目が決まるまでは大量配置へ進めない。最初にレビューする成果は、**実ゲームの背景として見える、白い段丘住宅・青いドーム・階段を含んだ1街区**にする。

制作方法は、現在と同じ**Blenderで自作 → GLBで書き出し → Godotへ配置**を基本案とする。既存の制作データが自作中心であること、専用の段丘地形とカメラ向け配置が必要なことから、この方法を推奨する。素材購入費・生成API費の追加0円を前提に組める。

リンク先のキットを購入して使う案も選べる。その場合は手元のパッケージ内容を確認し、モデル・テクスチャの取り出しとGodotでの表示試験を先に行う。商品説明にあるUnity Shader Graphの素材表現とPrefab構成はGodot用に組み直す作業を見込む。購入済みかどうか・実ファイルの内容は未確認。自作案と購入案の選択で変わるのは建築部品の制作工程であり、地形・構図・配置・性能検証はどちらにも必要になる。

実装時は、新しい制作データを `assets/environment/santorini_town/` 以下に用意し、既存の街と比較できる状態で進める。モデルの形はBlender、街区と目印の配置は保存されたGodotシーンから編集できる構成を目指す。既存GLBの読み込み箇所、StageEnvironmentの表示切替、夜の発光連動を主な接続点とする。

Godotのシーン・リソースを作成・編集するときは、接続先が `C:/AIQUIZ/AIQUIZ-Godot/` であることを確認し、Godot AIの操作を使って明示的に保存する。既存の[検証記録](/C:/AIQUIZ/AIQUIZ-Godot/assets/environment/harbor_city/VERIFICATION.md)には、GraphicsQualityに由来する編集画面プレビューのエラーがある。編集可能な街を仕上げる工程で再現を確認し、必要な呼び出し箇所を限定して対応する。

描画負荷は、街区単位の表示切替、遠距離用の簡略モデル、共通素材、植栽のインスタンス化で調整する。現在の13メッシュという数だけを基準にせず、マテリアル面数・実際の描画回数・CPU/GPUのフレーム時間を測る。近くに見える白壁は陰影を確保し、遠景の影と細かな装飾は画質設定と距離で抑える。

性能の仮目標は、同じ端末・解像度・画質・プレイ場面で、改修前に対する通常プレイの95パーセンタイルのフレーム時間増加を10%以内に抑えること。絶対的なFPS保証は基準測定後に設定する。街の読込みとヘリ出発時の停止、昼夜切替、リトライ後のメモリ増加も個別に確認する。現時点でこの目標を達成したという意味ではない。

完成判定は、次の結果を揃える。

- メニュー・通常プレイの1P/2P・ヘリの移動中で、白い段丘と青いドームを識別できる。
- 問題文、左右の回答、P1/P2の判別、カメラ移動中の視界が保たれる。
- 港・段丘・階段・建物が地形につながり、宙に浮く家や海面との隙間がない。
- メニュー、10問、エンドレス、チュートリアル、関係するサメ・ヘリ演出で街の欠落・遮蔽・ちらつきがない。
- コースの延長・飛行経路へ街が入り込まず、背景に不要な衝突判定が付かない。
- 昼・夕方・夜、各画質設定で破綻せず、性能の比較結果が残っている。
- Blenderの編集元とGodotの保存シーンから修正でき、再読込み後も配置が保たれる。

既存の `tests/harbor_city_runtime.gd` は13メッシュ、3種類の窓素材、幅約2kmの開放領域などを固定値で検証している。改修時は新しい街の仕様に合わせて検証を更新する。開放領域を変更する場合はコースと飛行の実際の占有範囲を測定して基準を作り、旧テストの閾値を変更する理由を記録する。

今のゲームルール・操作・P1/P2の配色・UIを土台に街を改修する計画であり、街の探索、建物の内装、住民AI、新しいゲームモードは今回の制作量に含めていない。Android版への導入・実機検証は、Windows/Godot版の採用後に別工程として見積もる。

次に実装へ進む際は、この基本方針をもとに「配置比較と代表街区の制作」を最初のまとまりとして着手する。
