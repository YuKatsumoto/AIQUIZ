# 新サドンデス 共通の流れ 仕様書（第1段）

2026-10-18作成。旧サドンデス（地下神殿、`docs/sudden_death_underground.md`、2026-10-04から廃止中）の作り直し。この文書は、どの種目でも共通の流れ（分岐・ヘリの迎え・移動の飛行・舞台へ降りる・導入・決着と帰還）を決める。種目ごとの仕様は同じフォルダーに置く。

> **2026-10-18、第1段の種目「ビタ止め10秒」を廃止した（ユーザーの指示）。** ビタ止め10秒専用のファイル（ルール・HUD・見せ方・島と小道具の素材と Blender の原本・左右の主観・テスト・仕様書 `bita_stop.md`）はすべて削除した。共通の流れ（分岐・ヘリ・雲・空のセット・舞台へ降りる・帰還・敗者の幽霊）と、それを支える既存のファイルの変更は残している。いまは種目がないので、`QuizGameState.SUDDEN_DEATH_GAMES` は空で、分岐の準備は整わない（`sudden_death_available` も false のまま）。代わりの第1段の種目を決めて作る。以下の本文に残るビタ止め10秒の記述は、その時点の設計の記録。

> **2026-10-19、種目を「つきやぶれ！スカイゲート」（`sky_gate.md`）に替えた。** 乗り込み・移動・降下・迎え・帰還は 2 機のヘリと縄ばしごではなく、共用の水上機 C-130（`c130_float.md` 第6・8章）。監督の流れは `skygate_w6.md`。分岐・種目発表・雲の覆い・空のセット・敗者の幽霊・決着演出への戻り方は、この文書のとおり使う。パラシュートのコードは残してある（`QuizGameState.LEGACY_SUDDEN_DEATH_GAMES`）。

> **2026-10-18、サドンデスはルーレットをやめて、種目を1つだけにした（ユーザーの指示）。** 種目は「ひらけ！パラシュート」（`parachute.md`）。ヘリの床が抜けて落ちながら4択に答え、先にパラシュートが全開になった方の勝ち。空のセットから地上の舞台へ降りず（6.1節は使わない）、空のセットの海に浮かべた着地台で決着し、勝者は着地台で装備のエモートを踊ってから、縄ばしごで帰る（第10章）。泥んこ二択・クイズ腕相撲・人間カーリングとルーレットは作らない。

ローカル2P「10問」の決着演出が引き分け（DRAW）になったとき、2人がそれぞれのヘリの縄ばしごに飛びついて空へ連れて行かれ、バラエティー番組風の種目で決着をつける。種目は1つだけ（2026-10-18にルーレットをやめた）。

## 3. 全体の流れ

```
6.9秒 DRAW! → 8.4秒 審判の笛 → 8.6秒「SUDDEN DEATH!」
→ 9.0–10.4秒 両方のタワーが床まで沈む ／ 9.6秒〜 ヘリ2機が左右の海の上へ来て、縄ばしごを下ろす
→ 11.0秒 大型ビジョンで種目発表
→ 審判「乗りこめー！」→ 2人が床の端へ走り、縄ばしごに飛びつく
→ ぶら下がったまま上昇 → 雲に入る（ここで地上を隠し、2人を機内の座席へ）
→ 空のセットで2機が並んで飛ぶ（問題の生成と種目の準備が終わるまで）
→ 地上の種目：雲の覆いの中で種目の舞台へ切り替え、縄ばしごで降りる（空中の種目：そのまま）
→ 種目の導入（タイトル・ハテナの紹介・ルールカード）→ 本戦（種目ごと）
→ 決着：敗者は種目ごとの方法で退場（ビタ止め10秒はベンチが跳ね上がって爆散）。勝者は迎えの縄ばしごにつかまる
→ 雲を抜けてゴールへ → 勝者は縄ばしごで自分の台へ、敗者は幽霊になって画面の外から自分の台へ
→ 判定（6.9秒）から勝者の演出 → 操作可能
```

カメラは途切れさせずにつなぐ。カットを使うのは、雲の覆いの中と、種目のきっかけ（第12章）だけにする。

## 4. 分岐（DRAWから種目発表まで）

### 4.1 分岐の条件と0秒の準備

- 条件は旧と同じ：`uses_local_result_ceremony()`、`result_winner == 0`、`uses_sudden_death()`（`sudden_death_available`・`sudden_death_enabled`・チュートリアルでない・オンラインでない）。
- 同点を検出した0秒（`QuizGameState._begin_result_ceremony()`）に次を行う。
  1. 問題を確保する（`SuddenDeathQuestions.collect`。第9章）。
  2. 種目を決める。種目は1つだけなので常に `parachute`（2026-10-18 からルーレットはしない）。
  3. 種目の先攻などに使う乱数の種を決める。
  4. 種目の舞台と小道具の読み込みを別スレッドで始める（第14章のローダー）。
- 確保できなかったとき（全ての供給源が空）、または種目の読み込みを始められないときは、分岐せずに従来の引き分けで終える。

### 4.2 時刻表

時刻は決着演出の時計（`result_ceremony_elapsed`）。11.0秒で決着演出の時計を止め、それ以降はサドンデスの監督の実時間の時計で数える（表の時刻は11.0秒からの続き）。

| 8.4 | 審判の笛。両者が踊りを止めて審判へ振り向き、8.75〜9.55秒で腕を下ろす（既存の `SUDDEN_DEATH_BRANCH_TIME`） |

- 種目発表でビジョンへ寄るカメラは、11.0秒にその瞬間実際に映っている位置（決着演出のカメラ）から寄せ始める（`HeliSuddenDeathDirector._reveal_from`）。2026-10-18、ユーザーの指摘で2つ直した：
  1. 寄る直前にヘリを映す引きの画（10.4〜11.0秒）をなくした。
  2. 前は、計算上の引きの画から寄せ始めていたので、頭の1フレームでカメラが一瞬ヘリの方へ引いて見えた（測ると1フレームでビジョンから9.3m遠ざかっていた）。今は遠ざかる量0m。`tests/sudden_death_v2/parachute_runtime.gd` の `_watch_reveal_push` で毎回測る。
- ビジョンから引きの画へ戻るところ（13.8〜14.4秒）は今のまま（乗り込みの画へつなぐ）。
- 11.0秒で止めるので、11.2秒の操作可能（`INTERACTIVE`）と `clear_game()` は起きない。`clear_game()` をきっかけに動く `MatchReel` の確定と、得点板の番組への切り替えも一緒に遅れる（旧と同じ）。
- `provider.end_round()` も0秒では閉じず、帰還か打ち切りで閉じる（旧と同じ `_result_round_closed`）。

## 5. ヘリの迎えと飛びつき

### 5.1 迎えの位置

- 基準は台座の中心 `ResultCeremonyDirector.podium_center(state)`（床の上面 y = −1.2）。2人は台座の x = ±2.2（P1が +X）。
- 迎えの位置は、縄ばしごの一番下の横木が「床の端から外へ1.2m（x = ±13.2）、台座と同じ z、床から2.4mの高さ」に来るところ。ヘリの高さは、本編の登場と同じ縄ばしご（全長7.28m）から逆算する（約10m）。初期値で、実機で調整する。
- 2機の間は約26m離れるので、ローターは重ならない。台座の真上（x = ±2.2）では2機の間が4.4mしかなく、同時にホバーできないため、この位置にした。
- 床の外（|x| = 12〜27.2）は海で、横のスタンドは |x| ≥ 27.2 にある。ゴールの観客席は台座の22m奥なので、迎えの位置の上空は空いている。

### 5.2 飛びつき

本編のメニューのStartで、走って縄ばしごに飛びつき、ぶら下がったまま飛び去る動きができている（`menu_wall_background_preview.gd` → `setup_menu_departure`）。同じ関数を使う。

| 時刻 | 内容 |
| --- | --- |
| 12.8–14.0 | 2人が床の端へ走る（`PlayerController.update_intro_pickup_approach`、毎秒8m）。約9.8m |
| 14.0–14.6 | 最後の1.45mで跳び、一番下の横木をつかむ（`begin_intro_ladder_grab`、0.62秒）。つかむ音（`grip`） |
| 14.6–15.4 | 溜め：ジェットのポッドを広げる（`set_jet_charge`）。ぶら下がった2人の脚が揺れる |
| 15.4–17.4 | 点火して斜め上へ上昇し、観客席の上を越える。速さは毎秒6mから始めて加速する（メニューの78m/秒の急発進は使わない。カメラが追えないため）。観客は手を振る |
| 17.4–18.2 | カメラが2機を追って雲へ入る。雲の覆い（5.3節）の中で、地上を隠して空のセットへ替え、2人を機内の座席へ移し、縄ばしごを収納してハッチを閉じる |

- 2人の走り出しを0.15秒ずらす（P1が先）。同時に跳ぶと画が単調になるため。
- 縄ばしごは今、飛ぶ速さによる空気抵抗を持たず、真下に垂れる。ぶら下がったまま飛ぶ間（上昇と帰還）は、速さに応じて後ろへなびく項を足す。
- 機内まで引き上げる処理（`begin_intro_cabin_boarding`）は定義だけあって使われておらず、未検証。第1段では使わず、雲の覆いの中で座席へ移す。

### 5.3 雲の覆い

- 地上と空のセットを切り替えるための画面推移。0.8秒。カメラの前を雲の層が流れて画面が白くなり、抜けると別の景色になる。
- 作り：全画面のシェーダー（雲の模様を3D風に流す）と、空のセットの雲の板（`StagingClouds`）。白くなりきった0.2秒の間に切り替える。
- 使う場所は、行きの「本編の舞台 → 空のセット」、地上の種目の「空のセット → 種目の舞台」（6.1節）、帰りの「種目の舞台（空中の種目は空のセット）→ 本編の舞台」。

空中の種目は、このまま空のセットで行う。地上の種目は、6.1節で舞台へ降りる。「ひらけ！パラシュート」は空中の種目で、巡航のあと縄ばしごで降ろさずに種目の導入へ渡す（`parachute.md` 第4章・第10章の `descent_mode()`）。決着は空のセットの海に浮かべた着地台で、帰還は10.1の地上の種目と同じ（着地台から縄ばしごに飛びつく）。

### 6.1 地上の舞台へ降りる

| 時刻 | 内容 |
| --- | --- |
| 0–0.8 | 2機が下り始め、雲の覆い（5.3節）に入る。覆いの中で、空のセットを片付け、種目の舞台の表示と環境（`WorldEnvironment`・太陽・霧）へ切り替える。2人を座席から、ハッチの上で待つ姿（`MK_CabinWait`、本編の登場と同じ）へ移す |
| 0.8–3.4 | 雲を抜けると、種目の舞台の上空。2機が舞台の降り場へ入り、減速してホバーする（本編の登場の `approach` と同じ減速） |
| 3.4–5.15 | 縄ばしごを出しながら、2人を横木まで下ろす（本編の登場の `lowering`、1.75秒） |
| 5.15–7.6 | 揺れて手を離し、Falling Idle で落ちて着地する（本編の登場の `swing` と手を離す処理。着地まで1.70秒、`Jump_Land`、`heli_land` の音と土ぼこり） |
| 7.6– | 2機は降り場の上で待つ（ローターを回したまま少し上がる）か、舞台の外へ離れる（種目ごとに決める）。種目の導入へ |

- 舞台は、本編の舞台と同じワールドの、本編の舞台から2km離れた位置に置く。行き来は雲の覆いの中だけで行うので、2つが同時に画面に映ることはない（旧の地下神殿で地上を隠していたのと同じ考え方）。
- 本編の登場の処理（`HelicopterArrivalDirector`）は試合開始専用で外から使えないので、同じ関数（`PlayerController` の `begin_/update_intro_ladder_hang`・`begin_intro_ladder_jump`・`complete_intro_ladder_landing`、`PhysicalRopeLadder` の `set_deploy_progress` など）を `SuddenDeathHeliRig` から呼ぶ。
- 2機の降り場は、ローターが重ならないよう12m以上離す（本編の登場の2機の間隔は12.56m）。

## 8. 種目の作り方（共通の決まり）

### 8.1 ルール側

- `scripts/core/sudden_death/` に、種目ごとのルールのクラスを置く。共通の基底 `SuddenDeathGame` を継承する。
- 基底が持つもの：`setup(questions, rng)`、`step(dt, input)`、`events`（出来事を積み、監督が読んで消す。旧と同じ）、`phase`、`winner`（0は未決着、1か2）、`decided_by`、`record()`（記録用の辞書）、`get_debug_snapshot()`、`extra_question()`（問題が尽きたときの補充。旧と同じ）。
- `step` は、1フレームが段階をまたいでも時間を順に配る（旧の `SuddenDeathState._step_phase` と同じ方式）。同じ入力なら 30 / 60 / 120fps で同じ結果になる。
- 旧の `SuddenDeathState`（早押しと沈むリフト）は使わない。

### 8.2 入力

| 操作 | P1 | P2 |
| --- | --- | --- |
| 回答（4択は左から ← ↑ ↓ →） | A / W / S / D | ← / ↑ / ↓ / → |
| アクション（ストップなど、種目ごとの意味） | Space | 右Ctrl |
| ルールカードを閉じる | Enter（どちらでも） | |

- 2択は ← →、3択は ← ↑ →（旧と同じ `SUDDEN_DEATH_CHOICE_KEYS`）。
- 押した瞬間だけを数える。押しっぱなしとキーの繰り返し（echo）は数えない。
- `GameWorld._record_sudden_death_key` が `_input` で時刻（usec）つきで記録し、`_feed_sudden_death_input` がフレーム内の秒に直して渡す（旧と同じ）。種類（`kind`）は旧の `buzz` を `action` に改名し、`answer` はそのまま。
- キーはフレームの頭でまとめて届くので、時刻の誤差は最大1フレーム（60fpsで約17ms）。2人とも同じ方法で測る。
- 一時停止（Esc）とウィンドウのフォーカスを失ったときの扱いは、種目ごとに決める。

### 8.3 見せ方側

- `scripts/world/sudden_death/games/` に、種目ごとの見せ方のクラスを置く。共通の基底 `SuddenDeathPresenter` を継承する。
- 基底が持つもの：舞台と小道具の準備（ローダーから1段ずつ呼ばれる）、導入のきっかけ、毎フレームの更新、出来事への反応、カメラの希望（監督へ渡す）、HUDの層、決着の見せ場、敗者の退場の始め方。
- 監督（共通）が受け持つもの：分岐、迎え、移動の飛行、舞台へ降りる、舞台の切り替え、導入、決着の後の帰還、打ち切り、カメラの最終決定、記録。

## 9. 問題の供給

- 0秒に確保する（`SuddenDeathQuestions.collect`）。取る順番は旧と同じ：①本編のラウンドで生成済み・検証済みで未使用の候補 ②オフライン問題 ③算数の自動生成。本編で出た問題は除く。画像を使う問題は除く。
- 確保する数は種目が決める（`QUESTION_COUNT` を種目ごとに）。ビタ止め10秒は4問。
- 選択肢の数も種目が決める（`prepare_choices`）。ビタ止め10秒は4択。
- オンライン生成のときは、11.0秒で種目用の問題を新しく生成し、正解をLLMで検証してから使う（旧と同じ `request_sudden_death_quizzes`）。生成のプロンプトの方針（旧の `SUDDEN_DEATH_FOCUS`「走りながら読める」）は種目ごとに持つ。届いた問題は本戦の前に差し替え、足りない分は0秒で確保した問題で埋める（`SuddenDeathQuestions.assemble`）。
- 本戦中に使い切ったら、算数の自動生成で1問ずつ足す（旧と同じ）。

## 10. 決着と帰還

### 10.1 時刻表（地上の種目。第1段はこれ）

時刻は決着（種目のルールが `winner` を決めた瞬間）から、実時間で数える。決着の見せ場の長さ（下の表の D）は種目ごとに決める。

| 時刻 | 内容 |
| --- | --- |
| 0〜D | 種目の決着の見せ場。敗者が種目ごとの方法で退場するところまで（ビタ止め10秒はベンチの座面が跳ね上がり、敗者が空中で爆散する） |
| D | HUD「P1 WIN!」（`show_winner`）。勝者の機が勝者の近くの降り場へ下りてきて、縄ばしごを下ろす（1.2秒）。敗者の機は来ない |
| D+1.2–2.4 | 勝者が縄ばしごへ走って飛びつく（5.2節と同じ動き） |
| D+2.4–3.6 | 勝者の機が、ぶら下がった勝者を連れて上昇し、雲へ向かう |
| D+3.6–4.4 | 雲の覆い（5.3節）。覆いの中で、種目の舞台を片付けて本編の舞台の表示と環境へ戻し、`end_sudden_death(true)` を呼ぶ（地表の値を戻し、勝者を確定して判定の手前で待つ） |
| D+4.4–7.0 | 勝者の機がゴールの手前の空から入り、勝者の台の真上でホバーする |
| D+7.0–8.6 | 勝者が手を離して自分の台へ降りる（`Jump_Land`） |
| D+7.2–9.3 | 敗者が幽霊（脱落者と同じ半透明の見た目）になって、画面の外（敗者の側の上空）から沈んだままの自分の台へ飛んでくる（`ResultFinaleStage.set_actor_flight` の `"ghost"` の型、2.1秒、`ghost_soul_rise`）。決着演出の間も幽霊のまま。2026-10-18 に排水口（`SurfaceDrain`）の噴き出しから変更 |

| D+10.0 | 待ちを解く（`release_result_return_hold()`）。判定（6.9秒）から勝者の演出（王冠・紙吹雪・勝者のダンス・敗者の膝つき・卵）を再生する |
| D+14.3 | 操作可能（決着演出の11.2秒）。ここで `clear_game()` |

### 10.2 空中の種目のちがい（第1段では使わない）

- D：敗者の座席のベルトが外れ、床下のハッチ（`set_hatch`）が開いて敗者が落ち、0.5秒後に縄ばしごの一番下の横木をつかんでぶら下がる。勝者は座席で喜び、勝者の機のハテナは手を振る（`wave`）。
- 2機ともゴールへ戻る。敗者の機は敗者の側の迎えの位置（5.1節）で止まり、敗者が手を離して海へ落ちる（水しぶき、観客がどよめく）。そのあと幽霊になって自分の台へ飛んでくる（10.1）。
- 勝者は機内から縄ばしごで下り（`begin_intro_ladder_hang` に機体の姿勢を渡す「機内から下りていく」動き）、横木から自分の台へ跳び降りる。

### 10.3 ゲーム状態

- `begin_sudden_death()`（地表の値を `SUDDEN_DEATH_SURFACE_FIELDS` に保存し、2人を生き返らせ、`STATE_SUDDEN_DEATH` にする）は、雲の覆いの中（17.4〜18.2秒）で呼ぶ。
- `end_sudden_death(hold)` は今、旧のルール（`SuddenDeathState`）が null でないことを前提にしている。基底 `SuddenDeathGame` の `winner` を読むように直す。
- 打ち切り（`abort_sudden_death`）は、空のセットや種目の舞台からでも雲を抜けてゴールへ戻り、2人を自分の台へ降ろしてから10.0秒の引き分けへ戻る。
- 帰還の間、敗者のタワーは沈んだまま（旧と同じ `Motion.side_heights`）。卵は敗者が台に着いてから（`allow_egg_target`）。

| フレーム時間（開発PC、高画質） | 迎え・移動・本戦・帰還で p95 16.6ms以下 |
| 雲の覆いの切り替え | 50msを超えるフレームなし |
| 空のセット | 地上を隠すので本編より軽い。オンラインの並走（描画の呼び出し 高824・低239）を上回らない |
| 予熱 | ヘリ・ジェット・煙・縄ばしご・雲・雲の覆いのシェーダーは、試合開始時の予熱（`game_world._prepare_world_visuals_under_cover`）に含める。予熱しないと点火で434ms止まった前例がある |
| 種目の舞台 | 0秒から別スレッドで読み込み、移動の飛行の間に組み立てと描画の予熱を終える（旧の地下神殿のローダーと同じ考え方。重い作業は1フレーム6msまで）。実写に近い島は大きいので、読み込み・組み立て・予熱の時間を測り、移動の飛行が長くなりすぎないか確かめる |
| 品質「低」 | 雲は下の層16枚、ハテナは軽い版、粒は0.35倍 |

- 縄ばしごは品質で切り替えておらず、1本で MeshInstance 47個・RigidBody 26個（kinematic）。2本と地上の舞台を同時に描く迎えの場面で、重さを測る。

### 仕様から変えた点・決めた点

- 種目発表は大型ビジョンで行い、画面のHUDには種目名を出さない（第2章・4.2節。ユーザーの指示）。ビジョンの「SUDDEN DEATH!」の副題は「種目は…！？」に変えた（旧の「地下神殿で決着！」）。
- 勝者の帰還：島では勝者が縄ばしごに飛びついて上昇し、雲の中で機内へ。ゴールでは本編の登場と同じく、機内から縄ばしごで降りて（降ろす・揺れ・手を離す）、自分の台の手前に着地し、台へ跳び乗る。そこで決着演出の人形に入れ替わり、タワーが伸び直す。
- 帰還の間、決着演出の舞台が勝者を確定して作り直されると、人形を隠す設定が消える。毎フレームかけ直す。
- 雲の覆いは全画面のシェーダー（`cloud_cover.gdshader`）。0.8秒で、0.4秒の真っ白の間に舞台を切り替える。
- 空のセットと島は、それぞれ本編の舞台から離れた位置（空：z −1800m・高さ140m、島：x +2400m）に置く。島の芝の高さは本編の床（−1.2m）にそろえる（PlayerController の着地・待機の足の高さが床をこの高さとみなすため）。
- 島と空のセットでは、本編の舞台（太陽を含む）を隠し、メインのカメラに島の Environment を付け、島の太陽を点ける。
- テスト（フレーム時間）では、HUD（`SuddenDeathHud`・`BitaStopHud`）の時計も監督の時計で進める（旧と同じ方式）。
