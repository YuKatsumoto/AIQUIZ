## どちらが「帽子と色で、自分だけのキャラに」に合うか

**B をおすすめする。** テロップの「色」が絵に出るのは B だけ。A は帽子しか替わらないので、「帽子と色で」と言いながら色が 1 回も動かない。
B は 1 拍ごとに帽子（0・2・4 拍）と色（1・3・5 拍）が交互に替わるので、「帽子と色」が頭から終わりまで途切れず続く。
パレット・人型マップ・選んだパーツの黄色い光のふちが映るので、「自分で塗れる」ことも一目でわかる。

| | A 帽子だけ | B 帽子と色 |
|---|---|---|
| テロップとの合い | 「色」が絵に無い | 帽子と色の両方が動く |
| 絵の静かさ | 静か。キャラが大きく、帽子が主役（海と空の背景） | 画面の左 45% が UI で情報が多い（1920×1080 なら字は読める） |
| 帽子の替わり方 | ゲームの ◀ ▶ と同じ滑る動き（古いのが左へ抜け、新しいのが右から入る）。モーションブラーがきれい | その場で「ポン」と替わる（ゲームの動き。滑らない） |
| UI | カスタマイズのパネル（小さく右） | オンラインのスキン設定のパネル（大きく左）。ヘリが背景に映り、S18（オンライン対戦）とつながる |
| 弱点 | 色が替わらない。1 カット目の頭は帽子なし | UI が多く、テロップの置き場が下か上の端に限られる |

AE で A の帽子の入りを活かしたい場合は、A の 0〜2 拍と B の 2〜6 拍をつなぐ案もある（どちらも同じ P1 のオレンジ・同じ 3 つの帽子で撮ってあり、背景だけが違う）。

## 帽子の選び方

今選べる 15 種（王冠は `HatData.RETIRED` で選べない）を全部撮って並べ（`hatsweep`）、色も輪郭もはっきり違う 3 つにした。
S02・S03 で見せているプロペラ帽・キツネ帽は避けた。

| 拍 | 帽子 | 理由 |
|---|---|---|
| 0 | サンタ帽 | 赤い三角、白いぽんぽん。背の高い輪郭 |
| 2 | カエル帽 | 薄い緑の丸。目が出ていて愛嬌がある |
| 4 | 海賊帽 | 黒い横長にドクロ。最後に一番派手なものを置く |

変えたいときは `pv_s20_runtime.gd` の `HAT_STEPS`（B は `STEPS`）。ほかの候補：シルクハット（黒・背高）、魔法使い（紫がかった灰・背高）、ヘルメット（黄）、ソンブレロ（横長）、卒業帽（黒・平ら）。
キリン・コーン・チキンは背が高すぎてバストアップに収まりにくい。

絵コンテ v1.2 の S20 の説明は「1 拍ごとに帽子が替わる（4 つ）」だが、今回は依頼どおり **2 拍ごとに 3 つ**（A）にした。B は帽子 3 つに、色の変更を 1 拍ずつずらして挟んだ。

## 案 A（`pv_s20_runtime.gd`）の中身

準備（撮影の前、約 8 秒）：1 人用のメインメニュー（設定の手順）を開き、昼の位相 0.25、`customize_btn.pressed.emit()` でカスタマイズを開き、
スキンのタブのボタンを `pressed.emit()` で押す。そのあと、カメラが落ち着くまで 3 秒待ってから撮り始める。

| テイクのフレーム | 拍 | 中身 |
|---|---|---|
| 1〜14 | 0 | 帽子なしの頭に、サンタ帽が右から滑り込む（`_apply_hat_change_animated(HAT_SANTA, +1)`。1 フレーム目の頭で呼ぶ。滑るのは 0.24 秒 = 約 14 フレーム）。`ui_click` |
| 57〜 | 2 | サンタ帽が左へ抜け、カエル帽が右から入る。入りは抜けより 0.03 秒おくれるので、約 5 フレーム（60〜64）は頭が空になる（ゲームの動き）。`ui_click` |
| 114〜 | 4 | カエル帽 → 海賊帽（同じ）。`ui_click` |
| 169 | 6 | 6 拍の終わり（168.75）。170〜173 は頭出しの余り |

- 呼ぶのは、カスタマイズ画面の ◀ ▶ が押されたときに呼ぶ `_apply_hat_change_animated(id, direction)`。◀ ▶ のボタンは 1 つ隣の帽子へしか進まないので、狙った帽子へは直接呼ぶ。
  ボタンを押さない分、クリック音（`ui_click`）が鳴らないので、`AudioManager.play_sfx(&"ui_click")` を同じフレームに足して `cues.json` に残した（ゲームのボタンと同じ音）。
- カメラは、スキンのタブのオービット変数（右ドラッグ・ホイールで変わるもの）を `_skin_cam_distance = 2.35`、`_skin_cam_target = (レーンの x − 0.17, 0.80, 0)`、`_skin_cam_yaw = 180`（キャラの正面）、`_skin_cam_pitch = 2` にして、
  ゲームのカメラ（Camera3D、画角 34°、レンズシフトの `h_offset` 0.30 はゲームのまま）に任せる。撮影中はカメラを動かさない。
  注視点を画面の右へ 0.17 m ずらして、キャラを UI のパネルから離してある（海賊帽のつばが UI に少し重なるくらい）。
- キャラの色は、カスタマイズ画面の 3D のプレビューが使う標準の P1（オレンジの体・薄い茶の頭）。カスタマイズ画面には色の設定が無い。
- UI：右にスキンのパネル（「スキン設定／対象プレイヤー: P1／◀ 帽子の名前 ▶／決定して戻る」）。「設定 / API 状態」とお知らせは隠す。

## 案 B（`pv_s20_skin_runtime.gd`）の中身

**通信なしで開いて撮れる。** `OnlineMenu` を開くだけではリレーにつながらない（つなぐのは「ランダムマッチ」「ともだちコード」を押したとき）。
それでも念のため `NetworkManager.relay_url` を使えない先（`ws://127.0.0.1:9`）に差し替えてから開いた。`report.json` の `network_state` は 0（OFFLINE）のまま。
同じやり方の既存のテスト `tests/online_skin_runtime.gd` を下敷きにした。

準備：`OnlineMenu.SCENE_PATH` を開き、トップ（`HOME`）でキャラが立って看板が出るのを待つ。看板を押したときと同じ `_on_page_action(&"skin", {})` でスキン設定のページへ。
ゲームのカメラ（`OnlineSkinCloseup`）が寄りきってから撮り始める。

| テイクのフレーム | 拍 | 中身 |
|---|---|---|
| 1 | 0 | サンタ帽（その場で替わる。`OnlineSkinPage._apply_hat` ＝ ページの ◀ ▶ と同じ）。体はオレンジ・全身が選ばれている。`ui_click` |
| 29 | 1 | 全身 → 青（パレットのマス 8 を `pressed.emit()`）。`ui_click` |
| 57 | 2 | カエル帽。`ui_click` |
| 78 | 2.75 | 3D のキャラの胸を選ぶ（`editor.select_part(&"chest")`。選んだパーツの光のふち） |
| 85 | 3 | 胸 → 黄（マス 3）。`ui_click` |
| 114 | 4 | 海賊帽。`ui_click` |
| 135 | 4.75 | 3D のキャラの腰を選ぶ（`&"waist"`） |
| 142 | 5 | 腰 → ピンク（マス 11）。`ui_click` |

- パレットは 3 行 × 13 列（色あい 12 + 無彩色 1）で、マスの番号は 行 × 13 + 列。行 0 = あざやかな色（列 3 = 黄、8 = 青、11 = ピンク）。変えるときは `STEPS`。
- パーツ選びのクリックは、ゲームでは 3D のキャラへのマウスのクリックだが、撮影では `editor.select_part` を直接呼ぶ。そのかわり、その位置（画面の座標）をクリックしたら当たるパーツ（`OnlineMenu._skin_part_at` のレイ判定）が、選ぶパーツと同じか
  を `report.json` の `done[].ray_hits` に残した（胸・腰とも一致した）。
- カメラ：ゲームの寄り（5.2 m・全身寄り）では帽子が欠けるので、`OnlineSkinCloseup` が動いたあとの上から（撮影のテイクは `process_priority` 1000 でそのあとに動く）、
  腰から 1.0 m 上を 3.3 m 離れて見る・画角 34°・キャラを画面の横 72% の位置に置く、で置き直した（キャラの正面。左の列にかからない）。
- 右上の「● オフライン」（通信の状態の表示）は隠した（PV の絵に「オフライン」と出ると誤解されるため。ほかの UI はゲームのまま）。
- 帽子はその場で替わる（ゲームのオンライン画面にはカスタマイズ画面のような滑る動きが無い）。

## 本物のマウスを使わない理由

最初は看板・パーツを本物のマウスのイベント（`Input.parse_input_event`）でクリックしようとしたが、**ビューポートが報告するマウス位置が、送った位置と違った**
（送った (1113, 462) に対して (975, 428)。窓の上に本物のカーソルがあると、OS から届くイベントとぶつかったと見ている）ため、看板が光らず、クリックが外れた
（`tests/online_skin_runtime.gd` は 1280×720 の窓で、同じやり方で動く）。
そのため、どちらのテイクもボタンの `pressed.emit()` とゲーム側の関数の呼び出しだけを使う。B は 3D の光（ホバー）が本物のカーソルで勝手に付かないよう、毎更新
`_skin_hover_3d`・`_skin_hover_map` を空に戻している。A のパネルの見た目（ボタンの押された色など）は本物のカーソルが乗ると変わるので、**撮影中は窓の上でマウスを動かさない**。

## 保存ファイル・通信を汚していない確認

- `PlayerSkinStore` は撮影のあいだ別の保存先（`user://pv_capture_player_skins.json`）・書き込み停止（`suspended = true`）。保留中の保存タイマーが、戻したあとの本当のファイルへ書かないよう、
  後片付けの最初に `reset_memory()` で捨ててから元の保存先に戻す。
- `report.json`：`real_skin_file_unchanged: true`（`user://player_skins.json` の SHA-256 が撮影の前後で同じ）、`settings_unchanged: true`（`user://settings.json`）。
  B は `network_state: 0`・`relay`（`ws://127.0.0.1:9`）も残している。
- 終わりの確認（`_check`）：A は帽子の変更が 3 回起きた・最後が海賊帽・スキンのタブのまま、B は 8 つの手順が全部済んだ・最後が海賊帽・スキンが標準色でなくなった・通信が OFFLINE のまま・パーツ選びの結果が一致、を満たさなければ `failures` に書く。

## できあがりの見かた・編集メモ

- どちらも画面全体に UI が映る（A は右のパネル、B は左の列）。テロップは、A は左下か上、B は右下か上の端に置くと、キャラと UI にかからない。
- `cues.json`：`ui_click` が帽子・色の替わりごとに 1 回（A は 1・57・114 フレーム、B は 1・29・57・85・114・142 フレーム）。ゲームの `se_lab/ui_click.ogg`。絵コンテは「ポン」だが、今のゲームの音はこれ。
- A は最初のコマだけ帽子が無い（0 拍で滑り込む。1〜3 フレームは空の頭）。前のカットから切ったとき気になれば、AE で頭の数フレームを詰める。
- 帽子のモデルは Poly Pizza（CC BY 3.0）のクレジットが要る（絵コンテのリスク表のとおり）。
