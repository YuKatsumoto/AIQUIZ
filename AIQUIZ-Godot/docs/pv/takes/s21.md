絵コンテ v1.2：10 拍（128 BPM で 1 拍 = 28.125 フレーム。テイクは 281 フレーム＋頭出し用の余り 4 フレーム = 285 フレーム）。
テロップ「決着は、スコアタワーで」（前半）は After Effects（レーン 6）。カメラ・HUD（得点の式と WIN!）・効果音はゲームのまま。

- 台本：`tests/pv_capture/pv_s21_runtime.gd`（`pv_take_base.gd` の上。下敷きは `tests/result_ceremony_runtime.gd`）。起動は `pv_take_bootstrap.gd -- take=s21`。
- 連番：`artifacts/pv_capture/s21_frames/`（pv_0001〜0285.jpg、`report.json`・`cues.json`）。`report.json` の `cut_in_frame` は 1。
- 確認用の一覧：`docs/pv/previz/check/s21_contact.jpg`。

## 勝ち負けのつく得点

| | 正解 | 残り HP | 得点（正解 ×（HP + 0.5）） |
|---|---|---|---|
| P1（プロペラ帽子） | 8 | 2 | 8 × 2.5 = **20.0（勝ち）** |
| P2（キツネ帽子） | 9 | 1 | 9 × 1.5 = 13.5 |

正解は P2 のほうが多いのに、残った HP で P1 が勝つので、得点の式の意味が 1 枚で分かる。撮影はデバッグ版なので引き分けだと
サドンデスへ進む（`game_state.gd` の `_begin_result_ceremony` → `uses_sudden_death`）。引き分けにならない得点にしたうえで、
念のため `gs.sudden_death_enabled = false` にした（`result_ceremony_runtime.gd` と同じ）。

準備（撮らない）：`hp_unit.gd` の `fixture(2)`、10 問を終えたところ（`current_index = 10` → ゴールへの走り）、2 人をゴールの手前に置いて
ゲームどおりゴール → 結果発表。結果発表の 3.0 秒まで 1/60 秒刻みで回してから撮り始める。勝った P1 はタワーの上でカンナムスタイル（エモートの 1 番目）。

## 時間の速さ（ゲームの演出 11.2 秒のうち、3.0〜9.6 秒を 10 拍に）

間は切らずに、時間の速さだけを変える（`_game_time_at`）。g は結果発表の時刻（ゲームの秒）。

| PV フレーム（本番画質） | g | 速さ | 中身 |
|---|---|---|---|
| 1 | 3.0 | 等速 | 得点の式のカード（正解数 8・9）、上に「スコアタワー」「正解数 × (残りHP+0.5) で勝負！」（ゲームの見出し） |
| 30・42・52〜60 | 3.3〜3.92 | 等速 | 残り HP（× 2・× 1）、「+0.5」、2.5・1.5 に合体 |
| 61〜135 | 4.0〜6.55 | 約 2.4 倍（前後 0.3 秒でなめらかに） | 66 からドラムロールでタワーがせり上がる。P2 のタワーが先に止まり、124 で P1 も止まる |
| 155 | 6.9 | 等速 | 5.5 拍目の頭で判定：判定の一打、「WIN!」（165 で出そろう）・紙吹雪。前半 5 拍のテロップが消えたあと |
| 156〜 | | 1.25 倍 | 192 で王冠が乗る、179 から負けた P2 のタワーが沈む、212 から観客席の荒くれが P2 へ卵を投げる |
| 226〜 | | 1.51 倍（決め直し） | 最初の「当たる卵」が 276 で P2 の背中に当たり、278 で殻が散る（下） |

本番（ultra・sub=8）の実際の値は `report.json` の `highlights`（`formula_correct`・`hp_bonus`・`climb`・`towers_stop`・`win`・`crown_land`・`loser_sinks`・
`first_egg_thrown`・`first_egg_hit`）と `plan`・`egg_adapt`。

- 卵を投げる時刻は観客席の乱数で決まり、画質（観客の数）・刻み・速さで変わる（等速で測ると最初の命中は 9.15 秒、別の回は 9.4〜9.6 秒）。
  そこで、最初の「当たる卵」（外れる卵は除く）が投げられた時点で、その卵の残りの飛行時間から、276 フレーム目に P2 に当たるよう残りの速さを
  決め直す（0.25 秒でなめらかに。0.8〜2.0 倍の範囲。本番画質では 226 フレーム目に 1.25 → 1.51 倍、低画質の確認では 1.25 → 1.45 倍）。
  決めた値は `report.json` の `egg_adapt`。最初の命中は本番・低画質とも 276 フレーム目。
- カメラはゲームのフィナーレのもの（高いタワーの回は、のぼる間は正面の 2 ショット、止まったら負けた側の横から勝った側を見上げる）。
  判定の揺れは sin のなめらかな揺れなので、sub=8 でも 4 重写しにならない。

## 編集（レーン 6）へ

- **ドラムロールは撮影の頭より前に鳴り始める**（結果発表の 2.0 秒）ので `cues.json` に入らない。`report.json` の `audio_before_take` のとおり、
  PV の頭に `score_drum_roll` を音の頭から 1.0 秒のところから置き、WIN! の `score_drum_finish`（`cut_at_frame`）で切る（早回しのぶん音のほうが長い）。
- テロップ「決着は、スコアタワーで」を上の中央に置くと、ゲームの見出し「スコアタワー」「正解数 × (残りHP+0.5) で勝負！」（上の中央、6.25〜6.5 秒まで =
  PV で約 2.2 秒まで）と重なる。下のカードの上（画面の中ほど）か、ゲームの見出しをテロップ代わりにする案がよいと思う。
- ゲームの画面の観客席の看板・スコアボードの文字は、まだ「AIQUIZ STADIUM」「AIQUIZ」のまま（ゲーム本体の素材）。

## 撮り方

```
Godot_v4.7.2-stable_win64_console.exe --path . --resolution 1920x1080 --fixed-fps 60 --script res://tests/pv_capture/pv_take_bootstrap.gd -- take=s21 quality=low tag=chk_s21
Godot_v4.7.2-stable_win64_console.exe --path . --resolution 1920x1080 --fixed-fps 480 --script res://tests/pv_capture/pv_take_bootstrap.gd -- take=s21 quality=ultra sub=8 tag=s21_sub8
python tools/pv/merge_subframes.py artifacts/pv_capture/s21_sub8 artifacts/pv_capture/s21_frames
copy artifacts/pv_capture/s21_sub8/{cues,report}.json artifacts/pv_capture/s21_frames/
python docs/pv/takes/lane3_contact.py docs/pv/previz/check/s21_contact.jpg artifacts/pv_capture/s21_frames "S21" 4 1:得点の式 ...
```

- 引数：`measure`（等速で 10 秒回し、卵の時刻などを report に書く下調べ）、`g0=` `verdict_beat=` `after=`（速さの決め方を試す）。
- 本番画質の撮影は `artifacts/pv_capture/GPU_LOCK` を作ってから走らせ、終わったら消した。かかった時間は 116 秒。
- 撮れた絵の確認（`_check`）：P1 が勝った・サドンデスへ進んでいない・WIN! が予定の 1 フレーム以内・王冠が乗った・卵が飛んだ・最初の命中が 276 の 2 フレーム以内。

## v1.9：S09 で遊んだ試合の本当の結果発表（テイク s21_play、2026-10-22 夜）

ユーザーの指示（スコアタワーも今の結果に合わせる）で、S09 に使った 2 人で遊んだ試合（`docs/pv/takes/s09_play.md`）の続きを撮った。
通しの S21 はこちらを使う（`pv_master.py` の `SIMPLE_TAKES`。前の回は `--take=S21:s21`）。

- 台本：`tests/pv_capture/pv_s21_play_runtime.gd`（`pv_s09_play_runtime.gd` の上）。記録 `s09_play_rec` のキーを同じコマで流し直し、
  記録が終わったあとも押したままの W で P1 がゴールまで走る。脱落した P2 は幽霊としてサメから自分の台へ跳び移り、結果発表になる。
  ```
  Godot_v4.7.2-stable_win64_console.exe --path . --resolution 1920x1080 --fixed-fps 60 --script res://tests/pv_capture/pv_take_bootstrap.gd -- take=s21_play inputs=s09_play_rec quality=ultra tag=s21_play_frames
  ```
- 撮るのは結果発表の 3.0 秒から 285 フレーム。時間の速さは上の表と同じ（等速 → 約 2.4 倍 → 155 で WIN! → 1.25 倍）。卵の決め直しはしない
  （通しの S21 は 8 拍で、卵は映らない）。撮り終えたら連番と `cues.json` を pv_0001〜に詰め直す（`cut_in_frame` 1、テイクでは 5435 から）。
- 1 秒 60 コマで流し直すので、動きのブレ（sub=8）はない（S09 と同じ）。
- 得点：P1 は正解 7・残り HP 1 → **7 × 1.5 = 10.5（勝ち）**、P2 は正解 2・脱落 → 「2 × — = 2.0」。脱落した P2 は半透明の幽霊の姿で台に立つ。
- 見せ場（詰め直したフレーム）：HP 18、タワーがせり上がる 66〜124、WIN! 155、王冠が乗る 192。ドラムロールは撮る前（結果発表の 2.0 秒）から
  鳴っているので、`audio_before_take` で頭から 1.0 秒のところから置き、WIN! で切る。
