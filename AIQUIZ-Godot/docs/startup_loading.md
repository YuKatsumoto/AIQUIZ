# 起動時のローディング

通常起動の入口は `res://ui/startup_loading.tscn`。黒背景、左下のフレア、
`LOADING...` と進捗バーを表示してからメインメニューへ移る。
ステージ遷移のローディングキャラクターは従来のヘッドスピンを維持する。

2D（黒カバー、`LOADING...` ラベル、進捗バー）がソース・オブ・トゥルースである。
フレアの3Dは、カバーと文字を数フレーム描いたあとに遅延生成する。
`LOADING...` を SubViewport へ焼き込んで元ラベルを消すことはしない。
プレビュー用 SubViewport の debanding は常時オフにし、共有フォントアトラスを壊さない。

## 準備の範囲

- メニューとその依存シーン、共通アニメーション、選択中とメニュー用のエモート、ヘリ素材をバックグラウンド読み込みする。
- 読み込み完了を確認してから取得し、`GameManager.startup_resources` にセッション中保持する。
- 独立した描画領域で両プレイヤーのラグドール・死亡破片、死亡小窓、2択/4択の問題壁、正解・爆発・水しぶき・サメ接触エフェクト、サメとポータルを試し描画する。
- 実際のメニューの描画準備まで黒画面を保持する。メニューの入口アニメーションと初回チュートリアルは開示後に開始する。
- プレイ開始時にも既存の黒画面内で、選択後のプレイヤー素材と死亡小窓を準備する。
- リトライやメニューへの復帰では、起動ローディングを繰り返さない。

ロード済みフラグはディスクに保存しない。別PC、GPU、ドライバー変更後も同じ準備を行う。
問題生成の通信を起動時に開始したり、現在のラウンド・死亡状態・履歴を変更したりはしない。
準備失敗時は黒画面にエラーを表示し、準備完了として進めない。

## 他PCで黒だけ出る件

以前は起動直後にフレアの3D SubViewportを作り、数フレーム後に `LOADING...` を画像へ転写して
元ラベルを非表示にしていた。別GPUでは転写画像が空になり、debanding が共有フォントを黒くし、
4pxの暗いバーは黒カバーに溶けることがあった。その結果、カバーだけが見えて文字とバーが欠けた。
いまはラベルを出し続け、バーの高さとコントラストを上げ、3Dは後から載せる。

## 検証

描画ありの Godot で `--script res://tests/startup_loading_bootstrap.gd` を実行する。
結果と画像は `artifacts/startup_loading/` に出力される。
`boot_2d.png` と `flair_0.png` に文字またはバーが写っていること。
F5とエクスポートは起動ローディングを通る。F6でメニューを直接実行するとこの入口を省略する。

初回コストをローディング内へ前倒しする変更であり、すべてのPCでの停止解消を保証するものではない。
メインスレッドでのシーン構築時にはローディングアニメーションも一時停止する場合がある。
別PCではフレーム時間と Mesh / Surface / Canvas / Draw の増加を測り、残る初回パスを追加する。
