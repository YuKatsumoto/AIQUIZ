# ローカル2Pの押し合い

対象は10問、エンドレス、そのゴール区間、ローカル2Pチュートリアル。1P、協力、オンライン、リプレイには適用しない。

相手へ向かう左右キーを押し続けると踏ん張る。2人の入力が0.10秒拮抗した後、同じキーを離して押し直すと、0.06秒の肩の予備動作を経て一押しする。初回接触や押しっぱなしでは一押ししない。ジャンプでも左右の順番を保ち、空中の相手も押せるが、攻撃側は接地が必要。

| 設定 | 初期値 |
| --- | --- |
| 通常の押し込み上限 | 1.2単位/秒 |
| 拮抗の成立 / 保持 | 0.10秒 / 最終成立から0.20秒 |
| 予備動作 / 個別受付間隔 | 0.06秒 / 0.28秒 |
| 相殺する押下時刻の差 | 0.05秒以内（境界を含む） |
| 一押しの追加移動 | 0.45単位 / 0.12秒、二次の減速曲線 |
| 被弾中の左右入力 | 25%、0.12秒後に即復帰 |
| 踏ん張り / 攻撃 / 被弾の上半身傾き | 6度 / 14度 / 10度 |
| 攻撃終了 / 被弾復帰 / 接触解除 | 押下から0.24秒 / 0.18秒 / 0.10秒 |
| 接触の粒 / 命中の線 | 3個・0.15秒 / 6本・0.16秒 |
| エフェクト再利用枠 | 4組 |

0.45単位は相手が無入力の場合の追加移動。相手が抵抗する場合は25%の左右入力が合成される。落下確定後は既存の落下処理に戻る。Z座標、ジャンプの力、自動前進、採点、壁速度は押し合いから変更しない。

## 構成

- `scripts/core/local_push_duel.gd`: 入力の押下・解放、左右の順番、接触、拮抗、受付間隔、予備動作、相殺、ノックバック、演出時刻。最大1/240秒の刻みと入力/発動時刻の境界で進める。入力を両者分読み終えてから発動を決める。
- `scripts/core/game_state.gd`: 対象モード判定、`submit_local_push_key`、`suspend_local_push`、`get_local_push_pose`、`local_push_event`。従来の`update`引数と通信・リプレイの形式は維持。
- `scripts/world/game_world.gd`: 実際のキーイベントを時刻付きで収集し、同一フレームの解放・再押下も渡す。echoは破棄。ポーズ・フォーカス喪失で履歴と未発動の攻撃を破棄し、再開時は現在のキー状態に同期する。
- `scripts/world/player_controller.gd`: 毎回通常姿勢を生成した後、既存の上半身パーツに肩の動きを加える。前回の加算分を復元するため蓄積しない。接触中は走行を土台とし、エモート選択は保持する。死亡、落下、ヘリ演出を優先する。
- `scripts/effects/particle_spawner.gd` / `local_push_effects.gd`: 4組の小さな粒・衝突線。床の高さと肩の表面に合わせる。生成したフレームで寿命を二重に進めない。カメラ揺れ、画面フラッシュ、時間停止、音は追加しない。
- `scripts/core/tutorial/duo_tutorial_flow.gd`: 左右移動の次に押し合いを追加。拮抗→P1の命中→P2の命中を順に認定し、相殺は数えない。表示する方向キーは実際の左右配置から決める。

## 検証の再実行

プロジェクト直下で実行する。

```powershell
.\Godot_v4.7.2-stable_win64_console.exe --headless --path . --script res://tests/local_push_unit.gd
.\Godot_v4.7.2-stable_win64_console.exe --headless --path . --script res://tools/test_lateral_movement.gd
.\Godot_v4.7.2-stable_win64_console.exe --headless --path . --script res://tools/test_choice_contract.gd
```

`local_push_unit.gd`は30/60/120fps、両者と左右の入れ替え、同時入力の境界、40ms間隔の連打、解放猶予、echo、逆方向/左右同時、キャンセル、空中の順番、ノックバック量、入力復帰、対象外モード、チュートリアル順序を検証する。

Forward+のメインシーンを起動した後、Godot AIのgame_evalで実行する。

```gdscript
var probe = load("res://tests/local_push_runtime.gd").new()
get_tree().root.add_child(probe)
probe.run.call_deferred()
```

実ゲームの通常メニュー開始処理、ヘリ到着、Enter開始、カウントダウンを経由する。キーは`InputEventKey`を通常の入力経路へ渡す。ゲームの更新を停止せず、接触から復帰まで各描画フレームの画像と状態を記録する。ドアと端のケースのみ、操作開始前に配置を設定する。問題はオフラインを使う。

結果は`artifacts/local_push/unit.json`、`artifacts/local_push/runtime/report.json`。連続画像は同フォルダの各クリップ名のフォルダへ保存する。録画のGPU読み戻しで描画fpsが下がるため、30/60/120fpsの数値比較は独立したロジック検証で行い、動画は記録した時刻差で再生する。

ヘッドレス実行時の既存の`loading_character_3d.gd:311`のダミーテクスチャ警告や終了時のリソース警告は、Forward+の実ゲーム検証と区別する。

## 2026-09-13の確認結果

- 数値・入力・モード・チュートリアルの216項目が成功。30/60/120fps、P1/P2、左右配置の全12組で追加移動は0.45000005単位、命中回数は1回。40ms間隔の連打でも各fpsで受付は0.28秒間隔に揃う。
- Forward+の実ゲーム55項目が成功し、365フレームを連続保存。2択から4択の最終問題まで両者の正解通過、ゴールの押し合い、空中への命中、ジャンプによるキャンセル、ポーズ・フォーカス復帰、海への押し出し、P2の死亡ワイプ、チュートリアルの順番付き完了を確認。
- 既存の左右移動チェックと、選択肢契約の168ラウンド・3258項目も成功。
- `artifacts/local_push/runtime/preview.mp4`は最終版の短い実入力動画。`ten.mp4`、`goal.mp4`、`endless.mp4`、`edge.mp4`、`tutorial.mp4`、`door9.mp4`には各ケースの連続映像を保存。
