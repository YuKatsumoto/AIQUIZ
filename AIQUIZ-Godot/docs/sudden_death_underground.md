# 2Pサドンデス「早押し水没リフト」仕様書

> **2026-10-04、サドンデスを一旦廃止した（第20章）。** コード・舞台・素材・テストはすべて残してあり、`QuizGameState.sudden_death_available` を `true` に戻せば元どおりになる。

2026-10-01作成。2026-10-02〜03に「地下神殿ラン」としてマイルストーン1〜4を実装（第15〜18章）。2026-10-03、本戦を「早押し水没リフト」に作り替え、水を流体シミュレーションにした（第19章）。地下神殿ランは自動前進・正解の開口へ横移動・後ろから迫る脅威・押し合いという4つの要素が地上の本編と同じで、ゲームとして酷似していたため。

ローカル2P「10問」のスコアタワー演出が引き分け（DRAW）になったとき、そのまま終わらずに地下の巨大水槽で決着戦を行う。両者のタワーが沈み、昇降台ごと縦穴を降りて地下神殿へ着く。地下では2人がそれぞれのスコアタワーに乗り、タワーがリフトとしてせり上がる。トンネルから鉄砲水が噴き出して神殿を満たし、流れる水の上で早押しクイズを行う。正解すると相手のリフトが、間違えると自分のリフトが沈み、先に水に沈んだほうの負け。

首都圏外郭放水路（通称「地下神殿」）の調圧水槽の雰囲気を参考にする。ただし、ゲーム内は架空の施設とする。施設名・管理者名・ロゴ・実際の看板は再現しない。

## 2. 全体の流れ

```
スコアタワー演出（DRAW） → 両方のタワーが沈む → 床が開く
→ 降下ローディング（黄色いランプの縦穴） → 地下神殿の天井から降りて着地
→ 導入（照明点灯・審判・2人がリフトのタワーへ歩いて乗る・タワーがせり上がる・鉄砲水・ルールカード）
→ 本戦（早押しクイズ。決着まで1問ずつ）
→ 決着演出（敗者のリフトが水に沈む） → 勝者を昇降台が迎えに来る → 上昇
→ 地表で勝者の演出／敗者が排水口から噴き出す → 操作可能
```

暗転は使わない。地表から地下神殿まで、カメラを途切れさせずにつなぐ。

### 2.1 DRAW演出からの分岐

既存の判定は演出開始時（0秒）に `QuizGameState._begin_result_ceremony()` で確定し、6.9秒で見せる。同点を0秒で検出できるため、その時点から地下神殿と問題の準備を始める。降下開始まで約11秒、読み込みに使える。

| 演出時刻 | 内容 |
| --- | --- |
| 0–6.9秒 | 既存どおり。判定前は勝敗が分からない |
| 6.9秒 | 既存どおり「DRAW!」、両方の旗、観客「えーっ！引き分けー？」、卵 |
| 7.6–8.4秒 | 既存どおり両者が装備エモートを踊る |
| 8.4秒 | 審判が笛を吹く。両者が踊りを止めて振り向く |
| 8.6秒 | HUD「SUDDEN DEATH!」のカットイン、サイレン、台座の床が回転灯付きの鋼製ハッチに変わる |
| 9.0–10.4秒 | 両方のタワーが同じ曲線で沈む（既存の敗者の沈みと同じ1.4秒） |
| 10.4–11.0秒 | 台座を囲む床がアイリス状に開き、縦穴の口が現れる |
| 11.0秒〜 | 昇降台ごと縦穴へ降下（第5章） |

分岐の条件は `uses_local_result_ceremony()`、`result_winner == 0`、設定のオンの3つ。対象外では従来どおり11.2秒で操作可能になる。

分岐時に止めるもの：

- `provider.end_round()`。サドンデスで問題を使うため、決着後の `clear_game()` まで遅らせる。
- 11.2秒の操作可能（`INTERACTIVE`）と `clear_game()`。試合記録 `MatchReel` の確定と、得点板の「AIQUIZ VISION」への切り替えもここに連動しているため、同様に遅らせる。
- 7.6秒以降の踊りのループ。8.4秒で止める。

### 2.3 決着演出と帰還

時刻は決着（負けた人の余裕が0以下になった瞬間）から、実時間で数える。

| 時刻 | 内容 |

## 3. ルール

### 3.1 基本

- 2人はそれぞれ自分のリフト（スコアタワー）の天面に立つ。走らない・横へ動かない・押し合わない・ジャンプしない。エモートも使わない。
- 早押し：P1はSpace、P2は右Ctrl（どちらも本編のジャンプキー）。押した瞬間だけを数え、押しっぱなしは数えない。
- 回答：押した人だけが方向キーで答える。P1は A / W / S / D、P2は ← / ↑ / ↓ / →。選択肢は画面の左から A・B・C・D と並び、下に各キーを示す。

| 選択肢の数 | A | B | C | D |
| --- | --- | --- | --- | --- |
| 2 | ← | → | | |
| 3 | ← | ↑ | → | |
| 4 | ← | ↑ | ↓ | → |

（P1は ← = A キー、↑ = W、↓ = S、→ = D。）その選択肢の数で使わない方向キーは無視する。

### 3.2 1問の流れ

| 段階 | 長さ | 内容 |
| --- | --- | --- |
| 問題の提示 | 1.1秒 | 「第N問」と選択肢が出る。この間の早押しは無効（押したまま待っても数えない） |
| 問題文 | 文字数 ÷ 8秒 | 問題文が1秒に8文字ずつ出る。早押しできる |
| 考える時間 | 5.0秒 | 全文が出てから、残り時間のバーが縮む。早押しできる |
| 回答 | 最大4.0秒 | 早押しした人だけが答える。押した時点で問題文は止まり、残りは隠れる |
| 判定 | 2.4秒 | 正解・不正解・時間切れを見せ、問題文の全文と正解の選択肢を出す。リフトが動く |

### 3.3 リフトの余裕

- 余裕は「天面が水面から何段上にあるか」を半段（0.75m）単位の整数で持つ。開始時は4（2段、3.0m）。
- 正解：相手の余裕が2減る（1段沈む）。
- 不正解、または早押しして4.0秒以内に答えなかった：自分の余裕が2減る。
- 誰も早押しせずに時間切れ：両方の余裕が1減る（半段沈む）。ただし余裕1より下へは沈まない（時間切れでは負けない）。
- 余裕が0以下になったら負け。1問で沈むのは多くても1人なので、同時に負けることはない。
- したがって、相手に2回正解されるか、自分が2回間違えると負ける（2問先取）。時間切れは、リードしている側だけを相手の高さへ近づける。リードしている側が押さずに待つだけでは勝てない。

### 3.4 早押しの同時

- 同じフレームの中の押した時刻（`GameWorld` がキーイベントの時刻を渡す）で比べ、早いほうが答える。
- 差が1/240秒以内なら、余裕が少ない（危ない）ほうが答える。余裕も同じなら、奇数問目はP1、偶数問目はP2。
- 早押しと回答が同じフレームに入った場合、早押しより後に押した回答だけを数える。

### 3.5 問題が尽きたとき

用意した8問（第4章）を使い切っても決着しない場合は、算数の自動生成で1問ずつ足して続ける。決着するまで問題は尽きない。

### 3.6 調整値（初期値）

`SuddenDeathTuning`。プレイテストで決める前提の初期値。

| 項目 | 初期値 |
| --- | --- |
| 開始時の余裕 / 罰（正解・不正解） / 時間切れ | 4 / 2 / 1（下限1） |
| 半段の高さ / 水位（床から） / 負けたリフトの沈み | 0.75m / 1.2m / 水面から0.7m下 |
| 問題の提示 / 文字の速さ / 考える時間 / 回答 / 判定 | 1.1秒 / 8文字毎秒 / 5.0秒 / 4.0秒 / 2.4秒 |
| カウントダウン | 1.8秒（「3・2・1」各0.6秒） |
| 決着から敗者が飲まれるまで / その後の待ち | 0.8秒 / 1.6秒 |
| 同時とみなす差 | 1/240秒（押し合いの刻みと同じ） |
| 問題を選ぶときの推定解答時間の上限 | 6.0秒 |

## 4. 問題の供給

- 8問を、同点を検出した演出開始時（0秒）に確保する（`SuddenDeathQuestions.collect`）。
- オンライン生成のとき（`llm_mode` がONLINEでAPIが使える）は、昇降台が縦穴へ降り始めたとき（演出11.0秒）にサドンデス用の問題を新しく10問生成する。生成した問題は正解をLLMで検証してから使い、検証で正解が変わった問題は使わない。降下は生成と検証が終わるまで巡航を続け、待ちが長いときは6m/秒へ落として真下を見下ろすショットにする。生成が45秒で終わらない・失敗した・使える問題が足りないときは、0秒で確保した問題で残りを埋める。オフラインのときは生成しない。
- 取る順番：①本編のラウンドで生成済み・検証済みで未使用の候補 ②オフライン問題（`offline_bank.json`） ③算数の自動生成。本戦中に8問を使い切ったら、算数の自動生成で1問ずつ足す（3.5節）。
- 試合の教科・学年・難易度を使う。本編で出た問題とは重複させない。
- 推定解答時間（`estimated_seconds`）が6.0秒以下の問題を優先する。画像を使う問題は除く。
- 選択肢は元の数のまま出す（2〜4）。5つ以上なら、正解と不正解3つを残して4つにする。並びは混ぜ直す。
- 確保できなかった場合（全ての供給源が空）は、分岐せずに従来の引き分けで終わる。

## 5. 降下ローディング（黄色いランプの縦穴）

地表のDRAW演出から地下神殿までを、暗転せずにつなぐ画面推移。地下神殿の読み込みと描画準備をこの降下の間に行う。動画や2Dのワイプではなく、ゲームと同じ3D空間で描く。そのため、両者の着せ替えや帽子がそのまま映る。

### 5.1 見た目

- 円形の鉄筋コンクリートの縦穴。内径14m。実物の立坑（内径約30m）より狭くし、壁とランプが画面に入る距離にする。
- 黄色いランプ：籠付きの防爆型ランプ。ナトリウム灯風の色（色温度約2000K、#FFA51F前後）。壁の4方向（0°・90°・180°・270°）に、上下5.0m間隔で同じ高さに並ぶ。
- 30mごとに深度表示板（「−10m」「−20m」…）がある。
- 壁面：1.5mごとの継ぎ目、ボルト穴、濡れた黒い染み、白華、垂直の水の筋、配管2本、ケーブルラック、籠付きの保守ハシゴ、昇降用のガイドレール2本。
- 空気：薄い霧、ランプの周りの光のにじみ、落ちる水滴、ほこり。
- 下は底の見えない闇。上は、地表の開口の昼光の円が小さくなっていく（最初の数秒だけ）。
- 昇降デッキ：鋼製の格子床に黄黒の縁取り、四隅のワイヤー。デッキの上に両者の台座（床リングはプレイヤー色）。

### 5.2 動きと時間

| 区間 | 時間 | 内容 |
| --- | --- | --- |
| 入口 | 0–1.4秒 | 地表の開口から入る。昼光から暗闇へ、露出を指定した曲線で切り替える（自動露出は使わない） |
| 加速 | 1.4–2.4秒 | 降下速度を0から10m/秒へ上げる |
| 巡航 | 2.4秒〜（最短3.0秒） | 10m/秒。ランプの段が0.5秒ごとに上へ通り過ぎる。準備（地下神殿の読み込みと、オンライン生成のときは問題の生成）が終わるまで続く |
| 減速 | 1.2秒 | 準備完了後、10m/秒から2m/秒へ下げる |
| 突入 | 2.6秒 | 天井の開口を抜けて地下神殿へ（2.2節の着地演出） |

- 準備が早く終わっても、巡航は最短3.0秒行う。通常は演出の約11秒と合わせて読み込みが終わり、巡航は3〜4秒になる見込み。
- 巡航が8秒を超えたら、速度を6m/秒へ下げ、カメラを真下を見下ろす角度に切り替える。
- 地下神殿の準備が25秒を超えた場合、または読み込みに失敗した場合は、減速して止まる（問題の生成を待っている間は打ち切らない）。その後、逆向きに上昇し、地表で従来の引き分けとして終える（操作可能へ移り `clear_game()`）。

### 5.3 深度表示

画面右の深度メーターは出さない（2026-10-02に変更）。待ちの表示は、ゲーム開始時の問題準備と同じパネル（「問題を準備中...」「しばらくお待ちください」、進み具合のバー、「AIクイズ生成中... (n/8)」）を、サドンデス用の問題を生成している間だけ画面中央に出す。地下神殿の準備が最短の巡航（3.0秒）を過ぎても終わらないときも、同じパネルで「地下神殿を準備中...」と出す。減速が始まったら消す。下の表示深度は、壁の深度表示板の数字と音の残響に使う。縦穴はループして描くため、表示は実際の移動距離から切り離して計算する。

```
準備完了前：表示深度 = min(降下開始からの秒数 × 10m, 60m + 8m × 準備の進捗)
準備完了後：減速と突入の3.8秒で、その時点の値から70mまで滑らかに進める
```

最短の場合（入口・加速・巡航で5.4秒）は約54mで準備が終わり、そこから70mへ進む。待ちが長い場合は60m付近で進みが遅くなり、準備の進捗に合わせて68mまで進む。

### 5.4 カメラ

| ショット | 内容 |
| --- | --- |
| A 入口 | 地表の演出カメラから、デッキを追って縦穴へ下りる |
| B 巡航 | デッキの縁の3.5m上から、両者の頭越しに55°見下ろす。ランプの段が上へ流れる。揺れは0.3°・0.5Hz、昇降の細かい振動を加える |
| C 長い待ち | 両者の頭上から真下の闇を見る。ランプの段が消失点へ集まる。Bからカットで切り替える |
| D 突入 | デッキが天井スラブを抜けたところで、カメラが上を向き、柱の森を見せる |

### 5.5 技術

- 縦穴は、ランプ1段分（5.0m）のタイルを12枚並べ、降下距離を5mで割った余りだけ上へずらして無限に見せる。巡航中のデッキとカメラは同じ高さに留める。
- タイルのライトマップは、3枚重ねでベイクして中央の1枚を使う。上下の継ぎ目で光が切れない。
- 人物を照らす実際のライトは、デッキに近い3段（12灯、影なし）だけ。タイルと一緒に使い回す。ランプ本体は発光材質と光のにじみで見せる。
- 縦穴のシーンは小さいため、ローカル2P「10問」の開始時の準備（黒画面の中）に含めて先に読み込んでおく。
- 地下神殿は、同点を検出した時点（演出0秒）で `ResourceLoader.load_threaded_request` により別スレッドで読み込む。現在、別スレッドの読み込みは起動時のローディングでしか使っていない。
- シーンへの追加は複数フレームに分ける（柱・小物・水門を部分シーンにする）。追加はショットC、またはショットBの暗い区間に行う。
- 描画パイプラインの準備は、起動ローディングと同じく、コンパイル数が3フレーム変わらなくなるまで待つ。
- 降下の動きは実時間の時計で進める（既存の `loading_character_3d.gd` と同じ方式）。メインスレッドが止まっても遅れず、止まった分だけ先へ飛ぶ。起動時には約2.1秒の停止が測定されているため、重い処理は暗いショットの間に寄せる。
- 地表の昼光が見えなくなったら（2.4秒以降）、地表のステージ（海・観客席・街・空）を隠し、地下用の環境（WorldEnvironment）へ切り替える。帰還時に戻す。

### 5.6 音

昇降モーターの低い唸り、ワイヤーの軋み、ランプの段が通過するたびの短い音、反響する水滴。深くなるほど残響を強くする。突入の瞬間に、大空間の反響へ切り替える。

## 6. 地下神殿のステージ

### 6.1 実物の参考値

- 調圧水槽：長さ177m・幅78m・高さ18m。柱59本（1本が幅2m・奥行7m・高さ18m、重さ約500t）。
- 第1立坑：内径約30m・深さ約70m。
- 出典：[日本コンクリート工学会 写真データベース](https://www.jci-net.or.jp/photo/db/detail.php?id=17&page=1)、[鹿島 インフラツーリズム特集](https://www.kajima.co.jp/news/digest/jul_2023/feature/04/index.html)

### 6.2 ゲームの寸法と配置

実物を参考に配置し直した架空の水槽。高さはすべて床面から測る。

| 部位 | 寸法・位置 |
| --- | --- |
| 空間 | 幅約90m（x = −45〜+45m）、長さ240m（z = −30〜+210m）、天井高18m |
| 柱 | 幅2m・奥行7m・高さ18m。前後方向に15m間隔。左右はx = ±12.9 / ±25.8 / ±38.7mの6列（中央列なし）。約90本 |
| 天井開口 | 着地点（z = 0）の真上。直径14mの円形で、縦穴につながる |
| 上流端 | z = −30m。流入トンネルの口（直径10m）とローラーゲート。鉄砲水はここから来る |
| 操作室 | 上流側の壁、高さ8mのバルコニー |
| リフトのタワー | 着地点の下流9m（z = 9m）。P1は x = +4m、P2は x = −4m（`SuddenDeathLayout.LIFT_*`） |
| 水 | 床から1.2m。上流端のトンネルから流れ込み、下流へ流れ続ける |
| 下流端 | z = +210m。排水ポンプの吸込口（格子）、保守用ハシゴ2本、高さ6mの通路と脱出ハッチ（いまは飾り） |
| 外側 | 外側の柱列は照明を当てず、霧と暗さで奥へ消す |

舞台は動かさず、ワールドの原点に置く。人物・カメラ・タワー・水はワールド座標で置く。カメラの描画距離は260m。

### 6.3 リフトのタワー

- 地表の決着演出のスコアタワー（`ResultFinaleStage.create_tower`：1.7m四方の台座、色帯付きの段の柱、四隅の紙吹雪の大砲）をそのまま使う。DRAWで沈んだタワーが地下でリフトとしてせり上がり、正解で相手のタワーが沈む。
- 段の柱（長さ10.8m）は台座の下へ伸び、床の下に隠れる。台座の天面の高さを変えるだけで、伸び縮みして見える。
- 天面の高さ＝水位＋余裕×0.75m（3.3節）。導入では床と同じ高さ（0m）から開始の4.2mまで毎秒2.4mで上がる。本戦の昇降は油圧の速さ（毎秒1.4m、止まる手前0.45mで減速）。負けたタワーは毎秒4.5mで水面の0.7m下まで沈む。
- 早押しした人のタワーの色帯が光る（発光を5倍）。
- 水の流体シミュレーションでは、タワーは半径0.85mの円の障害物で、天面の高さを床の高さとして持つ。水面より上なら水はタワーを避けて流れ、沈むと天面の上へ流れ込む。

### 6.4 実写に近い見た目の要件

目標：高画質・最高画質で、カメラを止めた静止画を参考写真と並べたときに、環境（建物・光・空気）が見劣りしないこと。

再現する要素：

- コンクリート：打放しの型枠跡（パネルの目地0.9×1.8m）、型枠の留め具の穴の格子、面取り、打ち継ぎの線、白華と錆の垂れ、床から1.5mの水位の跡（黒ずみと薄い藻）、場所ごとの汚れの濃淡。
- 床：濡れたコンクリート、浅い水たまり（鏡のような反射）、排水溝の格子、泥の溜まり。
- 金属：塗装した鋼材、手すり、ハシゴ、亜鉛めっきの配管、ケーブルラック。
- 空気：薄い霧、天井開口からの光の柱、照明の周りのにじみ、微細な塵、天井から落ちる水滴。
- 照明：白い投光器（約5000K）と黄色い保安灯（約2000K）が混在する。高いコントラストと深い暗部を作る。
- スケール感：人物（1.9m）と柱（18m）の対比。遠くの柱列は霧に溶ける。

静的な光はBlender（Cycles）で部品ごとに焼いた照度をUV2のテクスチャで持つ（第17章）。反射は30mごとの箱投影の反射プローブと画面空間反射（高画質以上）、空気は体積フォグ（標準以上）、陰影はSSAO（高画質以上）とSSIL（最高画質）、汚れはデカール、色調はAgXと色補正テクスチャ。

### 6.5 照明の計画

- 通路の柱（x = ±12.9m）の内側、高さ7mに投光器を柱1本あたり2基。すべて焼いてある。点灯演出（着地時）は、柱の行ごとの明るさの値を全ての舞台材質の共通シェーダーへ渡して作る。
- 実際に動かすライトは最小限にする：天井開口の影付きスポットライト1灯、行ごとの実ライト（人物・タワー・水だけを照らす）、本戦のキーライト。
- 本戦のキーライト：カメラの側（上流）、タワーから上流11m・高さ10.5mの左右2灯（影なし）で、それぞれのタワーと上の人物を照らす。カウントダウンから点く。
- 人物の見やすさのため、人物だけに効く弱い補助光を置く（ライトのカリングマスクを使う）。

### 6.6 水（流体シミュレーション）

`CisternFlow`（`scripts/world/sudden_death/cistern_flow.gd`、`shaders/sudden_death/cistern_flow.glsl`、`cistern_flow_surface.gdshader`）。

- 解き方：浅水方程式（shallow water equations）をスタッガード格子で解く。水深はセルの中心、流速はセルの面に置く。1ステップは「流速と泡を半ラグランジュ法で運ぶ → 風上の水深でフラックスを取って水深を更新する → 水面の勾配で流速を更新し、摩擦をかけ、乾いたセルからは流れ出さない」の3パス。RenderingDevice のコンピュートシェーダーで、1/120秒刻みで1フレームに最大4回進める。
- 範囲：地下神殿の全幅（x = −45〜+45m）と、上流端から下流42mまで（z = −30〜+42m）。0.3mの格子（300×240）。本戦のカメラは上流から下流を向き、手前の水と2本のタワーの周りがこの範囲に入る。範囲より下流は、水位に置いた平らな水面で続ける。
- 障害物：柱（固体）、端の壁（範囲の外）、リフトのタワー（6.3節）。
- 流入：トンネルの口（幅9.2m）の3列のセルに水位と流速を与える。噴き出しは水面2.2m・毎秒8.5m、6.5秒かけて水面1.7m・毎秒3.8mの定常の流入へ移る。
- 水位の保持：水のあるセルを目標の水位（1.2m）へ引き寄せる。下回っているセルは速く（毎秒1.2）、上回っているセルはゆっくり（毎秒0.25）。満ちるまでの間は目標を0.15m高くする。乾いたセルには足さないので、水はトンネルからの流れでだけ広がる。
- 流れ：満ちてから、水のあるセルの流速を下流向き毎秒1.2mへ寄せる（排水ポンプが水を引いている）。押す力ではなく流速を寄せるので、水面に勾配ができない。タワーは流れの中に立ち、後ろに渦と泡の筋ができる。
- 下流の端：範囲の最後の8mで水位と流速を吸収し、波を反射させない。
- 泡：流れが速い所、水が寄せて盛り上がる所（収束）、流れが渦を巻く所（渦度）、浅く速い流れの先端、トンネルの口で生まれ、流れで運ばれ、1.8秒で消える。
- しぶき：負けたタワーが水面を抜けるとき、落ちた人が水に入るとき、タワーが1段沈むとき（さざ波）に、輪状に水を押し上げて外向きの流れを与える。粒子のしぶきも出す。
- 表示：シミュレーションが毎フレーム書き出す画像（水面の高さ・流速・泡）で、セルの中心に1頂点の格子（300×240）を動かし、隣のセルの高さから法線を作る。流れの向きと速さで細かい波と泡の模様を運ぶ（2つの位相を交互に混ぜるフローマップ）。屈折、深さによる濁り、接する物の周りの泡、岸辺で薄く消える縁。反射は反射プローブ、高画質以上は短い画面空間の反射。
- 判定は持たない。ルールの水位は `SuddenDeathTuning.water_level`。
- 描画デバイスがない環境（ヘッドレス）ではシミュレーションをせず、水位に置いた平らな水面だけを出す。
- 鉄砲水の先端は、流入から毎秒6.8mで扇形に広がるとみなし、しぶきと霧の粒子を乗せる（シミュレーションの結果をCPUへ読み戻さない）。
- 負けた人の体は、既存のラグドールを流れで下流（カメラから遠ざかる向き）へ毎秒4.5mで運び、泡の中で回し、沈めて消す（`FloodTumble`）。

## 7. カメラ

本戦は `SuddenDeathDirector` が全てのショットを決め、`CameraController.set_director_pose` で渡す。

## 8. HUD

`SuddenDeathHud.set_quiz` に演出が毎フレーム問題の状態を渡す。

- 問題パネル（画面上部）：「第N問」、状態（「わかったら早押し！」「P1 回答中」「P1 正解！」「時間切れ」など）、問題文（1文字ずつ。流れている間はカーソル、早押しで止まると「…」）、残り時間のバー（考える時間は橙から赤、回答中は押した人の色）。問題文は幅に合わせて折り返す（日本語は文字単位、英語は単語単位）。
- 選択肢（画面下部）：A〜Dの箱。下に、押す前は両者のキー（P1は A W S D の橙、P2は ← ↑ ↓ → の青）、回答中は押した人のキーだけ。判定では正解を緑、選んだ不正解を赤にして揺らす。
- リフトのゲージ（左右の端）：P1は左、P2は右。余裕を半段ごとの4つの札で示し、下に水面の線。回答中は押した人の枠が点滅する。
- 呼び出し：「P1 早押し！」「P1 正解！」「P1 不正解！」「答えられず…」「時間切れ！ 両方のリフトが沈む」「P2 OUT!」。
- 既存の要素（カットイン・審判の掛け声・ルールカード・カウントダウン・勝者の表示・黒帯）はそのまま使う。
- 日本語と英語の両方を用意する（`use_english_ui`）。

## 9. 音

- バス「SuddenDeath」（残響・低域通過・リミッター）。深さに合わせて残響を強め、突入で大空間の残響へ切り替える。
- 早押しクイズの音（手続き生成）：早押し（明るい2音の上行）、正解（ピンポン・ピンポーン）、不正解（ブッブー）、残り3秒の刻み、時間切れ（低い銅鑼）。
- タワーの昇降は油圧の音、敗者が水に落ちる音は水の噴出の音を使う。鉄砲水の噴き出し、ゲートの開放、昇降モーター、審判の声、照明の点灯など、降下と導入の音は第16章のとおり。
- BGMは10dB下げる。

## 14. 未決事項とリスク

- 早押しの公平さ：1台のキーボードを2人で使うので、キーボードによっては同時押しの取りこぼしがある。左右のジャンプキー（Spaceと右Ctrl）は離れているが、実機で確かめる。
- 時間切れの半段：リードしている側だけが相手の高さへ近づくが、決着は罰でしか起きない。両者が押さない限り続く（問題は算数で補充される）。プレイテストで、考える時間（5.0秒）と合わせて決める。
- 問題文の速さ（毎秒8文字）と問題の長さ。長い生成問題は読み切る前に押す駆け引きになるが、遅すぎると間延びする。
- 水の見た目：流れ・渦・泡は動いているときに最もよく見える。静止画では暗い水面に見える。泡と流れの強さはプレイテストで調整する。幅90mの水槽を幅10mのトンネルから満たすので、水が見える範囲の奥まで届くのに約11秒かかる。導入の途中（2人が歩いている間）にゲートを開け、カウントダウンを鉄砲水から11秒後以降にしている。
- 人物はブロック調で顔がないので、振り向きは姿勢でしか分からない。
- 導入の長さ（着地からルールカードまで6.2秒、カウントダウンは着地から13秒後以降）。

### 仕様から変えた点・決めた点

- 静的な光は LightmapGI ではなく、Blender（Cycles）で部品ごとに焼いた照度をUV2のテクスチャで持つ。LightmapGI はエディターでしかベイクできず、行ごとの点灯演出（6.5節）では焼いた光に行の明るさを掛ける必要があるため。符号化は縦穴と同じ (E / light_max)^(1/2.2)、Aは焼いたAO。区画は同じ区画を3つ並べた真ん中を焼き、隣の投光器の光も入る。汚れ（1.5mの水位の跡、白華、錆の垂れ、天井のしみ）は焼いた光の側に掛けてある。
- 実ライトは舞台に当てない（舞台のメッシュはレイヤー11だけ、実ライトの cull mask から外す）。人物・水門列・波は、行ごとの実ライト（投光器の位置）と、今の列のキーライト、弱い環境光で照らす。ライトマップのプローブは使わない。
- 今の列のキーライト：列の上流13m・高さ10.5mの左右2灯（影なし）で、門の正面・LED板・走者を照らす。カウントダウンから点き、走者の列に合わせて次の列へ移り、出口ハシゴでは端の壁を照らす。その区画の明るさにも従う。
- 水門列はBlenderの部品ではなく、コードで作るメッシュ（2・3・4択の3種類を一度だけ作って共有）。開口の数と位置が列ごとに変わり、LED板の文字も毎回描くため。
- 文字は `quiz_wall` の Label3D ではなく、フォントのグリフをLEDの格子（1灯＝1テクセル）へ直接描いた画像で出す（SubViewportなし）。問題は16字までは1行、それより長いと2行に分け、読点の近くで改行する。分数は本編と同じ小さい数字の分数。1.5倍の層も持つが、サドンデスのカメラは走者との距離が一定なので切り替えは使っていない。
- 選択肢の扉を割る演出（本編の壁）はやめ、不正解では開口のシャッターが0.18秒で落ちる（火花・水しぶき・赤の回転灯）。正解の通過は緑の信号と閃光。決着した列は全てのシャッターが0.25秒で閉じ、全員不正解の列は全て上がる。
- 3択・4択の開口の並びを左右反転した（`SuddenDeathTuning.door_xs`）。走者は +Z へ走るのでカメラから見て +X が左になり、本編の問題壁と同じ座標ではAが画面の右に来ていた（マイルストーン1からの誤り。2択はすでに反転してあった）。どの選択肢数でもAが左。
- 舞台のデカールの台紙はBlenderで作らず、組み立てツールが手続きで描く。舞台の面に属する汚れは焼いた光に入っている。
- 反射プローブの数に合わせて、`project.godot` の `rendering/reflections/reflection_atlas/reflection_count` を64から16にした（高画質の計測でVRAMが約370MB減った。反射プローブを使うのは地下神殿だけ）。

### 仕様から変えた点・決めた点

- 前面は流体シミュレーションではなく、Blenderで手続きに動かした固定の格子をVATに焼いた。流体シミュレーションの形はフレームごとに頂点数が変わり、ループもしないため。2.0秒でループし、列ごとに位相が x の滑らかな関数でずれる（仕様の「左右3分割して位相をずらす」を、継ぎ目のない形で行う）。
- VATは位置（半精度EXR、アルファに泡の量）と法線（PNG）の2枚。幅4096、1フレーム5行、48フレーム。前面の格子は通路（24m）だけでなく空間の全幅（±45m）。
- 前面は不透明（高画質以上で画面空間反射が効く）。後ろの水面は半透明で、屈折、深さによる吸収、流れに沿った法線と泡の筋、柱や門の足元の接触の泡。Godotの画面空間反射は半透明に効かないので、高画質以上は水面のシェーダーの中で短い画面空間の反射を辿る（それ以外は反射プローブ）。
- 水の色は濁った灰褐色。前面は暗い水に、崩れる唇・顔を落ちる泡・つま先の泡の帯だけが白い。前面の光の当たらない面が真っ黒にならないよう、濁りの中の散乱をわずかに発光として足す（その付近の照明の明るさに比例）。
- 鉄砲水はトンネルの口（幅10m）から扇形に広がり、進むにつれて全幅を満たす（トンネル寄りも後から満ちる）。

### 決めた点

- 時間切れでは余裕1より下へ沈まない（同時に負けないため）。1問で沈むのは多くても1人。
- リフトは地表のスコアタワーをそのまま使う。DRAWで沈んだタワーが地下でせり上がる。
- 本戦のカメラは上流から下流を向く（P1を画面の左にするため。走者が +Z を向く本編と同じ左右）。2人は振り向いてカメラを向く。
- 水は浅水方程式をGPUで解く。試合の展開（誰がいつ沈むか、誰が落ちるか）に応じて水が動くので、Blenderで焼く方式（流体シミュレーションの結果を連番やVATにする）は採らなかった。
- 満ちた後の流れは、押す力ではなく流速を下流向き毎秒1.2mへ寄せて作る（押す力では下流に水が溜まり、タワーの所で水面が1.77mまで上がった）。
- 鉄砲水は導入の2.0秒（2人がタワーへ歩いている間）に出す。ルールカードを閉じても、鉄砲水が出てから11秒たつまでカウントダウンを待つ（水が見える範囲の奥まで届くのを待つ。それより早いと、最初の問題の間に奥の床が乾いて見えた）。
- 決着の0.5倍速の間も問題パネルを出しておき、迎えのデッキが来たら消す。

## 20. 一旦廃止（2026-10-04）

ユーザーの指示で、サドンデスを一旦廃止した。ゲーム内容を作り直す予定で、地下ステージは首都圏外郭放水路の調圧水槽の再現に差し替えてある（`docs/surge_tank_reproduction.md`）。作り直しでは、水の流体シミュレーション（`CisternFlow`）は重いので使わない方針。

### 動き

- ローカル2P「10問」で引き分けになっても分岐せず、従来の引き分けで終わる（`QuizGameState.uses_sudden_death()` が常に false）。
- 地下の準備（縦穴・昇降台・排水口の水柱の組み立て、描画の予熱、問題の確保と生成）は行わない。いずれも `uses_sudden_death()` を見て止まる。
- 設定画面の「サドンデス（2P 10問の引き分け）」の行は出さない。プレイヤーが保存した `user://settings.json` の `sudden_death_enabled` は読み書きをそのまま残す（戻したときに前の選択が生きる）。

### 残してあるもの

コード（`scripts/core/sudden_death/`、`scripts/world/sudden_death/`、`scripts/ui/sudden_death_hud.gd` と各所の分岐）、シーン（`scenes/sudden_death/`）、素材（`assets/environment/surge_tank/`、`assets/hazards/flood_wave/` など）、シェーダー、テスト、この仕様書は消していない。書き出し（`export_presets.cfg`）からも外していない。

### 元に戻す

`scripts/core/game_state.gd` の `static var sudden_death_available: bool = false` を `true` にする。設定画面の項目・分岐・地下の準備が元どおりになる。

### テスト

サドンデスのテストの入口（`tests/sudden_death_bootstrap.gd`、`tests/sudden_death_settings_reel_bootstrap.gd`）で `QuizGameState.sudden_death_available = true` にしてから動かすので、廃止中もこれまでどおり実行できる。舞台・読み込み・HUD・音・縦穴の単体のテストは分岐を通らないので、変更していない。
