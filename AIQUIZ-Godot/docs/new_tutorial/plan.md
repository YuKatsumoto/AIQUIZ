## 2. 設計の原則

1. **読ませるより体験させる。** 画面に出す文は一度に1つ、1行まで。キーは壁や看板に大きく描く
2. **失敗しても終わらない。** ミスしたら1秒以内にそのレッスンの始めへ戻る（位置・壁・ハート）
3. **1回に教えるのは1つ。** 本番で出てくる順に並べる
4. **本物で練習する。** 本物のステージ・壁・ハート・サメ・のこぎり・ゴーストを使う
5. **自分のペースで進める。** 説明中はコンベアを止め、練習の壁はゆっくり来る。本番の速さは各コースの「しあげ」だけ
6. **いつでも抜けられる。** Esc で『ゲームに戻る』／「このレッスンをスキップ」／『タイトルに戻る』
7. **本編から独立させる。**（6章）

## 4. コースとレッスン（たたき台）

### 共通の作り

- **コース選択**：メニューの「チュートリアル」から。5枚のカード（スタンプ・人数・目安時間）。おすすめ順に「次はこれ」を光らせる
- **初回の案内**：起動後のメニューの上に「初めてなら、チュートリアルで操作を確認しよう」［チュートリアルへ］［あとで］。［チュートリアルへ］で①、終わったら②をすすめる
- **レッスンの流れ**：ハテナの吹き出し → 壁か看板に課題 → プレイヤーが動く → できたら ✓・効果音・ハテナが喜ぶ → 次へ
- **看板の壁**：ドアの代わりに大きなパネル（キーの絵・絵）を2枚持つ壁を説明板として使い、前方に止めて課題を書く。「説明は壁に書く」を、クイズを出さないレッスンにも広げる
- **進み具合**：画面の上に点（●●○○○）

- **ポーズ**：本番と同じポーズ画面に「このレッスンをスキップ」を足したもの。『タイトルに戻る』でコースをやめる（コース②の台本 1.1）
- **画面のコーチ**：本物の画面（ポーズ・リザルト・メニューなど）の上で、見てほしい所を光らせて付き添う。光っている所だけ押せる（コース②の台本 1.2）
- **練習の記録は送らない**：問題の成績・AI の改善・Firebase・分析・戦績・ハイライト・評価の送信に入れない

## 5. ハテナ（案内役）

- **舞台での位置**：いまの壁の前、ドアの外側（画面の左寄り）に立ち、壁といっしょに近づいてくる。壁を突破したら次の壁へジャンプで移る。課題を出すときは壁やハートを指す
- **吹き出し**：ハテナの頭上に1文ずつ。読み終わる時間を見て自動で進み、キーでも送れる
- **本編の役とつなげる**：ハテナは本編でもヘリの操縦士・のこぎりの操縦席・ゴールの審判をしている。③ではそのまま操縦席に座ってのこぎりを動かし、ゴールでは審判をする
- **今ある動き**：手をふる・前を指す（操縦士）、応援・拍手・ダンス（客席）、審判の旗（ゴール）、操縦（のこぎり）
- **新しく作る動き**（ライブの Blender で作る）：歩く・横や下を指す・あちゃー・うなずく・足をすべらせて落ちる など。最初は今ある動きで仮に組み、台本が固まってから作る
- **画面のコース**（②の後半・④・⑤）：その画面の3Dの背景に雲に乗って出る。メインメニューでは、のこぎりの操縦席のハテナが雲で出てくる（2026-10-25 決定。オンラインの画面では、ヘリの操縦士のハテナが出てくる）。声はなし（吹き出しの「ぽこっ」という音だけ）

## 6. 作りの方針（技術）

### 名前

新しいコードは `practice` の名前で作る（クラス名 `Practice〜`、フォルダ `scripts/practice/`）。旧版の `tutorial` という名前は撤去ですべて消える（本編が使っている3Dキーの2本も改名する）ので、新旧が混ざっていないかを grep で確かめられる。`lesson` は設定ホールの黒板の授業（`scripts/world/settings_hall/lesson_builder.gd`・`lessons/`）と紛らわしいので使わない。台本の「レッスン」は、コードでは `step` と呼ぶ。メニューの表示名は「チュートリアル」のまま（変えるなら9章）。

### 部品

| 部品 | 役目 |
|---|---|
| `PracticeCatalog` | 6コースの一覧・順番・スタンプの保存 |
| 台本データ（コースごと） | レッスンごとに「出すもの・ルール・セリフ・クリア条件・失敗したとき」を書いたデータ。文言の手直しはここだけで済む |
| `PracticeDirector` | ゲーム画面に1つ置き、台本を進めて本編の入口を呼ぶ |
| `MatchRules`（本編側） | ハート・のこぎり・押し合い・ゴースト・スクロールアウト・壁の速さ・コンベアの停止などを1か所にまとめた切り替え口。通常のモードはモードからこれを作るので、動きは今と変わらない |
| `PracticeCpu` | P2の入力を台本で作る。キーボードと同じ入力口に入れるので、移動・ジャンプ・押し合い・ゴーストがそのまま動く。メニュー背景のAIランナー（扉へ向かう・ゴーストで狙う）の考え方を土台にする |
| `PracticeOverlay` | 進み具合・ポーズ・スキップ |
| `HatenaGuide` | ステージのハテナと吹き出し |
| `PracticeCoach` | 本物の画面（メニュー・カスタマイズ・オンライン）で、ボタンを光らせて付き添う |

### 本編に足すもの（最小限）

- ルールの切り替え口（`MatchRules`）。本編のあちこちに「チュートリアルなら」の分岐を埋め込まない
- 台本から使う操作：選手を置く・壁を出す（問題と選択肢の数を指定）・コンベアの速さ・やり直し（位置とハートを戻す）・脱落させる（ゴーストの練習）
- 出来事の通知：今ある signal（正解・不正解・ハート・海・のこぎり・押し合い・ゴーストの突進）を使い、足りないもの（ジャンプした・エモートした・どのドアをくぐった）を足す
- 画面のボタンの目印：メニューなどのボタンに目印（meta）を付けて、コーチが見つけられるようにする
- 練習の問題は手書きの固定問題にする（AI生成にしない）。オフラインでも必ず同じように動く
- レッスンの試合は、ヘリの到着・問題の先読み・カウントダウンを通らずに始める

### 保存

`user://settings.json` に新しいキー（例：`practice_stamps`・`practice_intro_seen`）を足す。旧版のキー（tutorial_* の9個）は、撤去のときに、読み込んだ直後に消して1回だけ保存する。

### 確かめ方

- 単体テスト：台本の進み方、クリア・失敗の判定、スタンプの保存
- 実ゲームのテスト：各コースを自動操作で最初から最後まで通す（P2が人のときとCPUのときの両方）
- 見た目：レッスンごとのスクリーンショットと短い動画で、ユーザーに確認してもらう
- 本編が壊れていないか：節目ごとに既存のテスト（HP・押し合い・のこぎり・ゴースト・結果演出・オンライン）を回す

## 9. 決めること

### 決まったこと（2026-10-24）

- **締め切り**：決まった締め切りはない。品質を優先して、計画の順番どおりに進める
- **撤去前のバックアップ**：しない（旧版の未コミットの変更は、撤去すると戻せない）
- **作業する場所**：`C:\AIQUIZ` は `G:\AIQUIZ-Main` を指すジャンクションで、同じフォルダ。作業コピーは1つ。AGENTS.md の Godot の接続先（`C:/AIQUIZ/AIQUIZ-Godot/`）もこのフォルダ

- **`artifacts/tutorial_*` の旧資料**：消さずに残す（git の管理外で、本編に影響しない。消すならユーザーが手元で）

## 10. 旧版について（参照していないことの記録）

- 旧版の専用ファイル・資料・検証画像（`scripts` の tutorial ファイル、`docs/tutorial_renewal.md`、`docs/tutorial_keyboard/`、`artifacts/tutorial_*`）は開いていない
- ただ、本編のコード（`game_state.gd`・`game_manager.gd`）と README に旧版の分岐やコメントが埋め込まれていて、読んでいる途中で次のことが目に入った
  - 1人：操作のチェック、クイズの壁3つ、海とサメ、4択のボス壁を1枚、最後にカスタマイズの紹介
  - 2人：のこぎり（2人が警告の出る距離まで下がって戻る）、ゴーストの練習、ゴール後のスコアタワーで得点の説明
  - キーを3Dで示す
- 教える**内容**は本編のルールで決まるので、旧版と重なるのは避けられない。**教え方**は、目に入ったものと同じにならないようにした
  - ボス壁は単独のレッスンにせず、①の しあげの3問目に置く（本番の10問目と同じ山場）

  - のこぎりは距離の練習ではなく、ハテナが操縦するのこぎりから「にげきって 突破」
  - キーは浮かぶ3Dのキーではなく、壁と看板に書く
  - カスタマイズは①の終わりに付けず、独立したコース⑤にする
