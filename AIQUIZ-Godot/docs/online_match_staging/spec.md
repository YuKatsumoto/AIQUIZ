## 1. ねらい

小学生が「自分が出発して、相手が来て、対決が始まる」をひと目で分かり、待ち時間を「わくわくする時間」に変える。

| 柱 | 見せること | 判断の基準 |
|---|---|---|
| 出発 | 自分のキャラが自分の足でヘリに乗り込み、操縦士ハテナと飛び立つ | 乗る・座る・ドアが閉まる・浮く、が切れ目なく見える |
| 合流 | 相手のヘリが画面の外から来て、横に並ぶ | 相手が「来た」と 1 秒以内に分かる。2 機の並びが正面から見える |
| 対決 | カットインで 2 人と名前が向き合い、中央の稲妻の線が開いてステージになる | 名前が読める。読み込みの待ちを感じさせない |

成功の目安：
- マッチ成立からステージが開き始めるまで 7.3〜9.5 秒（読み込みを含む。v1.3 でユーザーの依頼により合流・並走を長くした。v1.2 までは 5.8〜7.5 秒）。
- 演出中に 50 ms を超える引っかかりがない（PC の「高」で 60 fps）。
- 「やめる」がいつでも 0.4 秒以内に効く。
- 2 回目以降の子のために「みじかい」演出を選べる。

## 2. 範囲

**範囲に入るもの**：ホームでの待機、乗り込み、離陸、上昇、検索中の飛行、合流、並走、VS カットイン、読み込み、中央の線が開く遷移。あわせて、ともだちコードの流れ、やめる、時間切れ、相手がいなくなったとき、通信が止まったときも扱う。

**範囲に入らないもの**：ステージの中のヘリ登場（本編の `HelicopterArrivalDirector` を新しいヘリに替える作業）。これは段階 2 とし、計画書の M9 で扱う（実施済み。計画書 9.4）。ステージが開いたあとは、今のステージの開始（開始の壁 → カウントダウン）につながる。

## 4. 流れ（状態）

```
IDLE ──[マッチング開始]──▶ BOARDING ──▶ COCKPIT ──▶ TAKEOFF ──▶ CLIMB ──▶ CRUISE（検索中）
  ▲                          │ やめる / 失敗 / 時間切れ（どこからでも）                │
  └──────── CANCEL（0.35 秒の暗転）◀──────────────────────────────────────────────┘
                                                                                     │ matched
CRUISE ──▶ JOIN ──▶ FORMATION ──▶ CUTIN_IN ──▶ CUTIN_HOLD（読み込み）──▶ SWAP ──▶ REVEAL ──▶（ステージ）
              │            │             │
              └────────────┴─────────────┴──[相手がいない（1 回目）]──▶ REQUEUE ──▶ CRUISE
                                                    （2 回目）──▶ CANCEL
```

| 状態 | 入る条件 | 出る条件 | 長さ（ふつう／みじかい） |
|---|---|---|---|
| IDLE | 画面を開く／CANCEL のあと | 「マッチング開始」または「コードを つくる」「はいる」 | ループ |
| BOARDING | 上のボタン（同時に `find_match` などを送る） | 座り終わる | 4.70 秒 ／ 2.94 秒（1.6 倍の速さ） |
| COCKPIT | BOARDING の終わり | 2.40 秒たつ | 2.40 ／ なし |
| TAKEOFF | COCKPIT の終わり | ホバーの高さで止まる | 2.60 ／ 1.60 |
| CLIMB（急発進） | TAKEOFF の終わり | ジェットブーストで飛び去り、暗転しきる | 4.40 ／ 3.00 |
| CRUISE | CLIMB の終わり | `matched`、やめる、失敗 | ループ |
| JOIN | `matched`（下の「早めのマッチ」も参照） | 3.20 秒たつ | 3.20 ／ 2.20 |
| FORMATION | JOIN の終わり | 1.80 秒たつ | 1.80 ／ 1.20 |
| CUTIN_IN | FORMATION の終わり | 0.90 秒たつ | 0.90 ／ 0.90 |
| CUTIN_HOLD | CUTIN_IN の終わり | 最短の長さ＋読み込み済み＋開始の合図（下の条件） | 最短 1.40 ／ 0.80 |
| SWAP | CUTIN_HOLD の終わり | 次の画面で準備ができた（`reveal_current`） | 読み込みしだい |
| REVEAL | `reveal_current`（読み込みが終わった） | 稲妻 → 溜め → 割れて、火花を散らし震えながらゆっくり開く（23・25） | 3.20 ／ 2.20 |

**早めのマッチ**：CRUISE より前に `matched` が届いたら、覚えておき、次の「出口」で JOIN へ進む。

| どこで届いたか | どうするか |
|---|---|
| BOARDING の途中 | 残りを 2.6 倍で進め（v1.3。v1.2 までは 2.0 倍）、COCKPIT を飛ばし、TAKEOFF を 1.0 秒（0.15 秒で浮く）にして、浮いて 0.6 秒で JOIN |
| COCKPIT・TAKEOFF の途中 | 1.5 倍で進め、浮いて 0.6 秒で JOIN |
| CLIMB の途中 | すぐ JOIN（カットで切り替える） |

早めのマッチ（上の 3 つ）では、JOIN・FORMATION・CUTIN_HOLD の最短を「みじかい」の長さ（2.20・1.20・0.80 秒）にする。乗り込みの始まりでマッチしても、マッチから開くまでを 9 秒以内に収めるため（受け入れ基準 A6）。

**開始の合図（CUTIN_HOLD を出る条件）**：
- ホスト：CUTIN_IN が終わった時点で `start` を送る（今の「VS 表示の秒数」で送る仕組みを置き換える）。CUTIN_HOLD は、最短の長さがたち、読み込みが終わったら出る。
- ゲスト：`start` を受け取り、最短の長さがたち、読み込みが終わったら出る。`start` が CUTIN_IN より前に届いたら覚えておく。
- 12 秒たっても `start` が来ない（ゲスト）：「あいての つうしんを まっています…」を出したまま待つ。リレーの猶予（30 秒）が切れたら、D12 の流れ（探し直し）。

## 5. 座標と目印

- **ヘリの座標（H）**：原点はヘリの接地点（スキッドの下面の中心）。+x は機体の右、+y は上、-z は機首。ヘリの GLB の原点は、そこから `skid_drop` = 1.75 m 上にある。
- **目印**：乗り込み・座る位置は `helicopter_boarding_layout.json` の `MK_*` を使う。コードに数値を書かない（例：`MK_IdleSpot`、`MK_BoardStand`、`MK_Step`、`MK_DoorSill`、`MK_SeatFront`、`MK_SeatPassenger`、`MK_SeatPilot`）。
- **ヘリポート**：作り直した 1 つだけのパッド（八角形、対辺 18 m）。デッキの上面は y = -1.2（`stage_constants.gd` の `FLOOR_TOP_Y`）、パッドの中心は原点。ヘリの向きは Y 回りに -90°（機首が +X）で、ヘリポートの配置 JSON（`helicopter.yaw_deg`）に書く。ゲームの太陽（WeatherCycle：方位 +X・-Z の上、仰角 60°）が待機のカメラ（H の左前）の後ろに来るので、ヘリの左の面とキャラが順光になる。
- **人の足の高さ**：プレイヤーの足の裏はポーズによって BASE_Y より 0.14〜0.19 m 低い。乗り込み中は、足の裏の実測を目印の高さ（地面 0、ステップ 0.35、床 0.70）に合わせる。

## 6. ショットごとの仕様

カメラの位置と注視点はヘリの座標（H）で書く。ヘリが動くショットでは、カメラもヘリに合わせて動く。S1〜S5 のカメラは「21. カメラワーク（v1.2）」の動くカメラ（下の表の「カメラ」の行はその要約）。

### S0 待機（IDLE、ループ）

| 項目 | 内容 |
|---|---|
| ヘリ | パッドの中心に止める。ローターは前後の向きで止める。左のドアは閉じる。`Beacon` を 1 Hz で点滅させ、航空灯をつける。`Belt_L` は隠す |
| ハテナ | 右の席で `Pilot_SitIdle`。12 秒ごとにプレイヤーの方を見る（頭の向き ±25°、0.6 秒） |
| プレイヤー | `MK_IdleSpot` に立ち、`Idle_Loop`。向きはカメラへ向け、そこからヘリの方へ 30° 回す |
| カメラ | 位置 (-10.2, 3.1, -8.6) → 注視点 (-1.0, 1.7, -0.6)、画角 40°。9 秒と 7 秒の周期で ±0.12 m／±0.06 m ゆっくり揺らす |
| 画面 | 今のホームのページ（左の列）。ヘリとキャラは画面の右 6 割に入る |

| 0.45〜1.50 | `MK_BoardStand` まで歩く（`Walk_Loop` を 1.0 倍） | | |
| 1.50〜1.95 | 1 段目：`MK_Step` へ（`Walk_Loop` の 1 歩＋足元を +0.35） | | |
| 1.95〜2.45 | 2 段目：`MK_DoorSill` へ。`Crouch_Fwd_Loop` に 30% まぜてかがむ | | `Pilot_SitIdle` |
| 2.45〜2.85 | `MK_SeatFront` へ移りながら機首の方へ 90° 回る | | |
| 2.85〜4.15 | `Sitting_Enter`（1.3 秒）。そのあいだに後ろへ 0.56 m すべらせ、`MK_SeatPassenger` へ | | |
| 4.00〜4.60 | | `Door_L` が閉じる（0.6 秒） | |

| 項目 | 内容 |
|---|---|

### S4 ジェットブーストの急発進（CLIMB、9.70〜14.10 秒。Helldivers 2 の発進のイメージ）

時刻は CLIMB の進み（0〜1）で決める（ふつう 4.40 秒・みじかい 3.00 秒で同じ形）。値は `OnlineStagingTimeline.BOOST`。

| 進み | ヘリ | カメラ |
|---|---|---|
| 0.00〜0.06 | 離陸から止まらずに、前へ進みながら上がり、左へ旋回し続ける | 離陸の画から切らずに、同じ位置のまま続ける（MV_Boost） |

## 11. 読み込み（D9）

1. オンラインメニューが開いたとき（2026-10-13。それまでは CRUISE／JOIN の始まり。早めのマッチで合流の最中に読み込むとカクつくため前へ出した）に `ResourceLoader.load_threaded_request("res://scenes/game_world.tscn")` を呼ぶ。
2. CUTIN_HOLD では `load_threaded_get_status()` を見る。終わっていれば `load_threaded_get()` で受け取る。
3. 読み込みに失敗したら、今と同じ `change_scene_to_file` に切り替える。その場合、ゲージは 60% で止める。
4. VS（CUTIN_HOLD）のあいだはステージ（ゲーム画面）の読み込みだけをする。ホストは SWAP でゲーム画面へ切り替えるとき（`_transition_to_game`）に `start_game(true)` で試合の状態だけを整え、問題生成（`provider.begin_round`）はゲーム画面の覆い（稲妻で割れて開く）が開ききってから `GameWorld._begin_deferred_quiz_generation_after_reveal()` で始める（開かないときも 6 秒で始める）。オンラインはオフラインの問題でも覆いの下で問題を待たない。問題の準備はヘリの投入と並べて進む。

## 16. 見やすさ・安全

- 白い光は 1 回の演出で 1 度だけ、45% 以下、0.06 秒以下にする。点滅は 3 Hz 未満にする（光過敏への配慮）。
- 揺れは 2D の層だけ、±6 px・0.18 秒まで。3D のカメラは揺らさない（21 の「ただよい」は 0.13〜0.34 Hz・向き 0.3° までのゆっくりした動きで、揺れではない）。ただし v1.3 の急発進の点火だけは、ユーザーの依頼（Helldivers 2 のイメージ）で一度だけ短く揺らす（0.45 秒、向き 0.55°・位置 5 cm まで。メニューのヘリ発進の揺れと同じ考え方）。
- 色だけに頼らない：「じぶん」「あいて」の札と名前を必ず出す（オレンジとブルーは色覚の型をまたいで見分けやすい組み合わせ）。
- 「みじかい」演出を選べる（D11）。

## 21. カメラワーク（v1.2）

乗り込み（S1）から検索中（S5）までのカメラを、止まった画の切り替えから「動き続けるカメラ」に作り直した。状態・長さ・通信は変えていない（A1〜A3 はそのまま）。

### 21.1 撮り方の決まり

| 決まり | 中身 | 理由 |
|---|---|---|

| 動機のある動き | どのショットも動く：追う（乗り込み）、寄る（操縦席）、上がる（離陸）、待ち構えてパン（上昇）、回り込む（検索中） | 止まった画の切り替えは「待たされている」感じが出る |

## 24. v1.5 で変えたこと：止まらずに旋回しながら発進する（2026-10-12）

ユーザーの依頼：「一旦上で止まってから点火するのではなく、点火していないときにもう飛び立ち、途中で止まらずに点火して猛スピードで飛んでいく」「真っすぐではなく、少し機体を傾けながら旋回して発進する」。続けて「旋回しながら上に機体を傾けながら上昇する」「ジェットブーストのスピードも上げる」「暗転するまでは機首の角度を元に戻さない」。

| 場所 | v1.4 | v1.5 |
|---|---|---|
| S3 離陸 | ホバーの高さ 8 m でなめらかに止まる | 止まらずに上がり続け、前へ進みながら左へ旋回しはじめる |
| S4 の溜め | ホバーのまま上下にゆれ、ポッドを広げる | 機首を上げて旋回しながら上り、飛びながらポッドを広げる（点火の直前で前へ 9 m/秒・上へ 10.5 m/秒、左へ 40°、傾き約 20°、機首 32° 上） |
| S4 の点火のあと | 真正面の 17° 上へまっすぐ（72 m/秒、機首 -12°） | 旋回の向きのまま 34° 上へ、120 m/秒。機首は 36° 上へ。旋回を約 20° 続けてゆるめ、傾きは 28° まで深める。機首の上げと傾きは暗転まで戻さない |
| S4 のカメラ | 低い所から見上げたまま、向きとズームで追う | クレーンで機体の高さまで上がって少し下がり、向きとズームで追う（旋回をカメラの側にして、傾いた機体の上面と水平線を見せる） |

- 道すじは `StagingFlight.departure(離陸からの秒, 浮く秒, 浮いてから点火までの秒)` の 1 本。点火までは `DEPART.pre_seconds`（4.5 秒）の長さで形を決め、みじかい演出・早めのマッチでは同じ道すじを速さを変えて通る。点火のあとは実際の秒で 72 m/秒まで加速する。位置は速さをシンプソンの公式で積む。
- 旋回は左（カメラの側）。右へ回すと、左にいるカメラへ機体の腹を向けて遠ざかるだけになり、空しか映らなかった（作業中のスクリーンショットで確かめた）。
- `tests/net/online_staging_runtime.gd` は、離陸の終わりで動き続けていること（3 m/秒より速い）、点火の前にもう飛んでいること（5 m/秒より速い）と、左へ 8° より深く傾いていることを確かめる。
