# ママチャリ競争 Phase 0 固定仕様

- ステータス: `FROZEN`
- 仕様版: `1.0`
- 固定日: `2026-07-20`
- 対象: デスクトップ版の通常ローカル2P競争

## 1. 目的

クイズ終了後に、両プレイヤーが最後まで操作して逆転を狙えるアスレチックレースを追加する。最初の競技をママチャリ区間とし、操作しているだけで速度感、駆け引き、失敗の笑い、追い上げが生まれることを最優先にする。

最終的なゲーム進行は次で固定する。

`10問クイズ → ママチャリ → 障害物ラン → 海上スイム → 最終スプリント → 結果`

フェーズ1では、ママチャリ区間だけをグレーボックスで完成させる。後続競技は状態と接続口だけを先に設計し、同時実装しない。

## 2. 対象と対象外

### 対象

- 通常ローカル2Pの10問モード
- クイズ終了からママチャリ開始までの遷移
- ママチャリの操作、挙動、障害物、チェックポイント、カメラ、HUD
- 後続競技へ渡せる競技状態と正規の勝者情報

### フェーズ1では対象外

- 1P通常モード
- チュートリアル1P/2P。2Pチュートリアルは当面、既存の短い `GOAL_RACE` を維持する
- オンライン対戦の本対応
- リプレイの本対応
- 障害物ラン、スイム、最終スプリントの完成版
- Tripo素材の最終品質調整。フェーズ1は仮モデルでも進められる

## 3. クイズから競技へのルール

- 10問終了時点で、旧ゴールレースを通常2Pの最終勝敗には使わない。
- 旧ゴール位置をママチャリ開始ゲートとして再利用する。
- 競技開始時に両プレイヤーを開始ゲートへ揃え、クイズ中に脱落演出を受けたプレイヤーも競技へ復帰させる。ママチャリを片方だけが遊ぶ状態にはしない。
- クイズ得点差は開始優位に変換する。高得点側は、得点差1点につき `0.12秒`、最大 `1.0秒` のスタート優位を得る。
- 得点そのものでは勝者を決めない。最終的な勝者はアスレチック最終ラインの到達順で決める。

## 4. 空間契約

現在の標準値 `wall_start_z=22`、`wall_spacing=30`、10問を前提に、次の相対式を正とする。将来クイズ数や間隔が変わっても、固定の絶対座標へ書き換えない。

| 地点 | 式 | 現在値 |
|---|---:|---:|
| 最終壁 | `wall_start_z + (target_count - 1) * wall_spacing` | `292m` |
| クイズ床出口 | `wall_start_z + target_count * wall_spacing` | `322m` |
| ママチャリ開始 | `quiz_exit_z + 15` | `337m` |
| ママチャリ終了 | `bike_start_z + 230` | `567m` |

- クイズ用ベルトコンベアは有限長にする。
- ベルトの先に15mの乗車・路面遷移帯を置き、専用道路へ接続する。
- ママチャリ道路の走行可能幅は `16m`、左右の安全帯を含むステージ全幅は既存の `24m` 内に収める。
- 道路、障害物、チェックポイントはベルトコンベアのスクロール材質やローラー形状を共有しない。

## 5. 230mコース構成

| 区間 | 相対距離 | 長さ | 狙い |
|---|---:|---:|---|
| 自動乗車・発進 | `0–15m` | `15m` | 操作説明と安全なスタート |
| 加速直線 | `15–45m` | `30m` | ペダルと慣性を理解する |
| コーンスラローム | `45–90m` | `45m` | ハンドル操作と抜き合い |
| 水たまり・段差 | `90–130m` | `40m` | 路面判断とコミカルな揺れ |
| 二択ルート | `130–185m` | `55m` | 安全ルートと短い難ルートの判断 |
| 上り坂 | `185–220m` | `35m` | 立ち漕ぎスタミナの使い所 |
| 自動降車 | `220–230m` | `10m` | 次の障害物ランへ自然につなぐ |

目標プレイ時間は初見で `25–35秒`。コース暗記後も単調な直線作業にならないことを受け入れ条件とする。

## 6. 操作契約

| 操作 | P1 | P2 | 仕様 |
|---|---|---|---|
| ペダル | `W` | `↑` | 押しっぱなし。連打を必須にしない |
| 左右操舵 | `A / D` | `← / →` | 速度に応じて旋回と傾きが変わる |
| ブレーキ | `S` | `↓` | 減速と立て直しに使う |
| 立ち漕ぎ | `Space` | `Ctrl` または `KP0` | スタミナを消費する短時間ブースト |

- キーボード同時押しの競合を避け、既存2P配列を維持する。
- ペダルはホールド式とし、腱やキーボードに負担がかかる高速連打を要求しない。
- フェーズ1で入力収集を専用データへ分離する。ママチャリ処理を `game_world.gd` の直接キー判定へ大量追加しない。

## 7. 乗り味の固定方針

実装は決定論的な疑似自転車物理とする。`VehicleBody3D` の完全物理シミュレーションは採用しない。ネットワーク同期、リプレイ、同着判定、再現性を優先しつつ、見た目には次を必ず出す。

- ペダル開始から最高速までの加速感
- ペダルを止めても少し進む慣性
- 速度が高いほど重くなる操舵
- 操舵量と横速度に連動する車体・ライダーの傾き
- 急操舵や障害物接触で増えるウォブル
- 先行者の後方に入ると明示表示されるスリップストリーム
- 後方プレイヤーだけを密かに速くする不透明なラバーバンドは使わない

初期チューニング値は以下から開始するが、これらはプレイテストで変更可能とする。

| 項目 | 初期値 |
|---|---:|
| 通常最高速 | `14.0m/s` |
| 立ち漕ぎ最高速 | `16.5m/s` |
| 基本加速度 | `5.0m/s²` |
| ブレーキ減速度 | `8.0m/s²` |
| 惰性減速 | `1.8m/s²` |
| スリップストリーム加算上限 | `1.2m/s` |
| 立ち漕ぎ連続使用目安 | `3.0秒` |

## 8. ミスと復帰

- ママチャリ区間では、障害物接触を死亡・永久脱落にしない。
- 軽い接触は減速とウォブル、強い接触は短い転倒演出にする。
- 転倒後は最後に通過したチェックポイントの安全地点へ `1.5–2.0秒` で復帰する。
- 復帰直後は短い無敵時間を付け、同じ障害物への連続衝突を防ぐ。
- チェックポイントは少なくとも `0m / 90m / 130m / 185m / 220m` に置く。
- 復帰位置は道路中央固定ではなく、相手や障害物と重ならない空きレーンを選ぶ。

## 9. カメラとHUD

- 2P共有カメラは両者の中点、速度、前後差から高さ、距離、FOV、先読み量を動的に決める。
- アスレチック中は既存の `SCROLL_OUT_LIMIT=14` による後方プレイヤー死亡を無効にする。
- 画面外プレイヤーマーカーは維持し、距離、向き、P1/P2色を表示する。
- HUDには速度、立ち漕ぎスタミナ、区間名、順位、相対距離、チェックポイント、スリップストリーム状態を出す。
- 画面中央を塞ぐ長文説明は置かず、開始直後に操作を一度だけ短く表示する。

## 10. 勝者判定

- 正式な状態は将来追加する `STATE_ATHLETIC_RACE` と `race_phase` が所有する。
- フェーズは `BIKE / OBSTACLE_RUN / SWIM / FINAL_SPRINT` とする。
- 正式な結果は `race_winner`、各プレイヤーの `finish_time`、`win_reason` が所有する。
- ゴール線をまたいだフレーム内の到達時刻を線形補間し、描画フレーム順に依存しない正確な時刻を記録する。
- 差が `0.05秒以内` の場合はフォトフィニッシュとし、クイズ得点が高い側を勝者にする。得点も同じなら引き分けとする。
- HUDや結果画面は勝者を再計算せず、必ず正式な結果フィールドだけを表示する。
- 現在の `goal_winner` とスコア表示の食い違いは、新しい勝者経路へ移行する際に同時に解消する。

## 11. 実装境界

フェーズ1以降は、既存の大型スクリプトへ処理を集中させず、少なくとも次の責務へ分ける。

- `scripts/core/bike_race_rules.gd`: 決定論的な速度、操舵、ウォブル、接触、復帰
- `scripts/world/bike_course.gd`: コース区間、チェックポイント、障害物、ルート
- `scripts/world/mama_chari_visual.gd`: 車輪、ハンドル、クランク、傾き、ライダー姿勢
- `scripts/ui/race_hud.gd`: 競技専用表示
- `scenes/mama_chari.tscn`: 1台分の表示ノードと当たり判定
- `scenes/bike_course.tscn`: 道路と配置物

`game_state.gd` は正式な競技状態と同期対象を保持し、`game_world.gd` は生成と接続に留める。

## 12. フェーズ1開始条件

- 本仕様と `tripo_asset_plan.md` を実装の正として扱う。
- 既存の未コミット変更を上書きしない。
- Tripo完成品を待たず、寸法契約どおりのプリミティブ仮モデルで乗り味を先に検証する。
- グレーボックス時点で、2Pが発進、操舵、ブレーキ、立ち漕ぎ、転倒復帰、ママチャリ終了まで遊べる。
- Fennaraのスクリプト診断で新規エラー0、`game_world.tscn` 検証で新規問題0を維持する。

## 13. 固定項目と調整可能項目

固定するのは、競技順、230m構成、ホールド式ペダル、非致死の転倒復帰、決定論的挙動、明示的スリップストリーム、正式な勝者情報、Tripo中心の素材方針である。

速度、加速度、カメラ補間、障害物個数、スタミナ回復、演出時間、音量はプレイテストで調整してよい。固定項目を変える場合は、この文書の仕様版を上げて変更理由を残す。
