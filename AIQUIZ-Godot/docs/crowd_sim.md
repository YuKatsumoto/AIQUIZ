# 観客の経営シム化（設計、2026-10-27）

左右のスタンドの観客を、経営シミュレーションゲームの客のように動かす。客が入場して席に着き、売店へ行き、試合の展開しだいで増えたり帰ったりする。
今の座った客の演技（docs/crowd_extras.md）はそのまま残し、その上に「席の状態」と「歩く客」の層を足す。
段階1（Godot だけの骨組み）・段階2（観客席の改修）・段階3（動きの追加）は 2026-10-28、段階4（試合との連動）・段階5（売り子）は 2026-10-29 に実装した（「段階1の実装」〜「段階5の実装」）。段階6（仕上げ）はまだ。

## 決まったこと

| 項目 | 決定 |
| --- | --- |
| 目指す姿 | 経営シム型。Planet Coaster やカイロソフトの客のように、人の出入りと流れが主役 |
| 入れる要素 | 席を立って歩く客、試合の展開で変わる客入り、売り子とのやりとり |
| 見せる場面 | プレイ中（画面の端のスタンド）と引きの演出場面（壁が割れた後・ゴールへの競争・ヘリの登場・決着演出） |
| 施設 | 新しく置く（売店・出入口）。観客席の形は手を加えてよい |
| 数字 | 見せない。入場者数などは画面に出さず、動きだけで感じさせる |
| 帰る客 | しっかり出す。ただし入りの下限は残す（「客入り」） |

対象は AIQUIZ STADIUM の左右スタンド（`aiquiz_stadium_stand.gd`）。ゴール観客席とサントリーニのテラス席は今のまま（「今の演出との関係」）。

## 今の観客（変えないもの）

- 左右スタンドは 1 ブロック 20 m に 114 席（6 段 × 19 席）。コースが 200 m なら片側 10 ブロック、密度 0.85 で片側約 1000 人。
- `GrandstandCrowd` がブロックごとに MultiMesh を作り（小道具なし／ありの 2 ドロー）、動きは `seated_spectator.gdshader` が焼き込んだ骨の行列（`SeatedSpectatorKit`）で再生する。CPU は客を 1 人も動かしていない。
- 客ごとのデータは `INSTANCE_CUSTOM`（位相・見た目 `look`・`habit`＝待機の動き＋役 × 8＋チーム × 128・速さ）。
- 合図は `CrowdCues`：判定・ゴール・失敗・HP・スタート・カウントダウン、驚きの波紋、ウェーブ、応援の拍、勝者のダンス。
- スタンドのノードは `PROCESS_MODE_DISABLED`。毎フレームの更新は `game_world._update_crowd()` から静的関数（`follow_cues()` / `update_mascots()`）で行う。シムもこの形に合わせる。

## 全体像

```
QuizGameState / CrowdCues ──▶ CrowdMood（見どころ・応援の手応え）
                                   │
                                   ▼
                  CrowdSim（片側に 1 つ：席の状態・欲求・客入り・行き先）
                  │                      │                       │
                  ▼                      ▼                       ▼
       座った客の MultiMesh       歩く客の MultiMesh         売り子（片側 1〜3 人）
       （来ている客を詰めて描く、    （道順に沿って CPU で動かす）
         台本の役）
```

- **座った客**：今のまま。来ていない客・離席中の客は描かない。立つ・座る・手を挙げる・手渡しは「台本の役」としてシェーダーで再生する。
- **歩く客**：席を立った客だけが、同じ見た目のまま歩く客のプールへ移る。片側の同時人数は画質で決める。
- **見えないブロックは歩かせない**：カメラに映らないブロックでは、状態だけを一瞬で変える（来た・帰った・食べ始めた）。歩くのは映っているブロックの客だけにする。少ない人数で経営シムの「人の流れ」を見せるための要。

## 観客席の改修（ライブの Blender）

`assets/aiquiz_stadium/source/blender/`（`aqs_parts.py` の `build_stand_block`、寸法は `dimensions.json` の `side_stand_block`）。
座標は Godot のブロック空間で書く。x はコースから外向き、y は上、z はコース方向で、通路はブロックの -Z 端（z = -10）にある。

### 今の形と問題

| 場所 | 今の寸法 | 歩く客にとって |
| --- | --- | --- |
| 前の通路 | 前の壁（x -0.6）と最前列の段の前端（x 0.6）の間、約 1 m。床 y 0.22 | 1 列で歩ける。売り子の通り道 |
| 通路の階段 | z -10 を中心に幅 2.2 m、12 段（踏み面 0.625・蹴上げ 0.2） | 上りと下りの 2 車線にできる |
| 各段（列） | 踏み面 1.25 m。座面の前が足の置き場 | 座っている客の膝の前を横に通る（重なりは許す） |
| 後方通路 | x 8.05〜10.9（奥行き 2.85 m）、床 y 2.72 | **ブロックの中央にブース（x 8.35〜10.65、z ±1.7）があり、前も後ろも 0.3 m 以下しか空かない。隣のブロックへ通り抜けられない** |
| 出入口 | 端のブロック（cap）にだけ、海側の船着き場へ下りる階段がある | 中ほどの席からは遠すぎる |

### 改修

1. **後方通路を広げる**：背面を x 10.9 から 12.3 へ（+1.4 m）。ブースの裏に幅約 1.65 m の通り道ができ、スタンドの端から端まで後方通路がつながる（コンコースになる）。背面の手すりも x 12.3 へ移す。支柱の列（x 0.2・5.4・10.3）は足さず、後ろへ 2 m 張り出す形にした。
2. **ブースを売店にする**：ブースの両端（z ±1.7 の面）に、売店の窓口（カウンター・ひさし・メニューの看板）を付ける。コース側の画面はそのまま残す。
   左スタンドは同じメッシュを 180° 回して使うので、両端に付けておけば、どちらのスタンドでもカメラ側（スタート側）に窓口が向く。
   行列は窓口から通路の階段のほうへ、ブースの前側（x 8.05〜10.65）に並ぶ（最大 6 人）。通り抜ける客はブースの裏を通る。
3. **出入口（下り口）を開ける**：通路を持つブロック（cap_end 以外）の、通路の上の脇の後方通路の床に、手すりで囲った下り口を開ける（x 10.95〜12.05、通路から +Z へ 0.6〜5.1 m）。
   通路側から 12 段でデッキの上面の踊り場まで下り、突き当たりに扉。客はここから入ってきて、ここから帰る。トイレは扉の先（見えない所）にあることにする。
   最初は「背面の手すりを切って裏へ下りる階段を付ける」案だったが、20 m ごとに外へ張り出してスタンドの外形が変わるので、床の穴に変えた（2026-10-28）。コースのカメラからは、下りる客が沈んで消えるように見える。
4. **端のブロック（cap_start / cap_end）**：ブースはないので、後方通路の幅だけをそろえる。
5. **歩く道を書き出す**：席の座標と同じように、`aiquiz_stadium_stand_blocks.json` に歩く道の点を足す。各段の通り道、階段の上りと下りの車線、後方通路の 2 車線、窓口の位置と行列の向き、出入口。Godot はこれを読んで道順を作る。

決まった寸法は `dimensions.json` と `DIMENSIONS.md` / `SCENE_PASSPORT.md` に反映し、作業した `.blend` を保存する。

## 客のモデル

### 客のデータ（`CrowdSim`、席ごとの配列）

| データ | 内容 |
| --- | --- |
| 状態 | 来ていない／着席／立つ途中／歩いている（行き先つき）／並んでいる／座る途中／帰った |
| チーム・役 | 今の `habit`。応援団長・ペア・タオルなどの固定の役は残す |
| 空腹 | 0 から 1 へ 3〜8 分で上がる（人ごとに違う）。0.7 を超えると、売店へ行くか売り子を呼ぶ |
| トイレ | 0 から 1 へ 4〜10 分で上がる。0.85 を超えると出入口へ行く（見どころが高いうちは我慢する） |
| 根気 | 帰るまでの我慢強さ（0.15〜0.45、人ごと） |
| 連れ | 隣同士の 1〜4 人。来るのも帰るのも一緒。ペアの役はそのまま連れになる |
| 来る時刻 | 開始時にもう座っている客と、遅れて来る客 |

客の割り当ては今と同じく種（seed）から決め、テストで毎回同じ結果になるようにする。

### 試合の空気（`CrowdMood`、試合全体で 1 つ）

| 値 | 上がる | 下がる |
| --- | --- | --- |
| 見どころ（0〜1） | 正解、接戦（HP の差がない）、ピンチ（誰かの HP が残り 1）。ゴールへの競争とサドンデスでは 1 に張りつく | 何も起きない時間が 15 秒を超えると少しずつ下がる（中だるみ）。大差（HP の差が 2 以上、片方が脱落）でも下がる |
| 応援の手応え（チームごと、0〜1） | そのプレイヤーの正解、相手の失敗 | 不正解、HP が減る。海に落ちる・サメ・ノコギリでの脱落では大きく下がる |

入力は `CrowdCues` と同じシグナル（`health_changed`、`question_winner_decided`、`player_entered_ocean`、`player_caught_by_saw`、サメ）とゲームの状態。

### 客入り

- 片側の目標の入りは、見どころと応援の手応えから決める。範囲は**下限 30 % から満席（＋立ち見）**まで。
- **帰る**：ファンは「見どころが低い」と「自分のチームの手応えが低い」の両方で、中立の客は見どころだけで決まる。帰りたい気持ちが根気を 10 秒続けて上回ったら、連れごと帰る。
- **戻る・来る**：見どころが上がると、帰った客の一部と遅れて来る客が出入口から入ってくる（盛り返すと客が戻る）。
- **下限 30 %**：画面の端のスタンドが空になると、スタジアムに見えなくなるため。応援団長・ペア・マスコットは帰らない。
- **立ち見**：満席で見どころが高いとき、後方通路の手すり沿いと通路の階段の上に立つ。立って応援する動きが要るので、後の段階に回す。

## 試合の流れと客の動き

| 場面 | 客の動き |
| --- | --- |
| 開始前・カウントダウン | 入りは 60〜70 %。遅れて来る客が出入口から入り、自分の席へ向かう |
| プレイ中（落ち着いた時間） | お腹がすいた客が、手を挙げて売り子を呼ぶか売店に並ぶ。トイレに立つ客や、遅れて来る客もいる |
| 盛り上がり（接戦・ピンチ・正解の連続） | 離席が減り（我慢する）、来る客が増える |
| 中だるみ・大差 | 離席と居眠りが増える。負けているほうのファンから、連れごと帰り始める |
| 脱落（海・サメ・ノコギリ） | そのプレイヤーのファンの手応えが大きく下がり、数秒後から帰る客が出る。2 人用では相手側が盛り上がる |
| ゴールへの競争・サドンデス | 誰も帰らない。歩いている客と並んでいる客は**走って席に戻る**。駆け込みの客も来る |
| 判定後 | 勝った側は残って踊る（今の勝者のダンス）。ダンスが始まると、負けた側のファンと中立の客の一部が順に帰り始める。1 人用・協力・エンドレスで負けたときは、全体の一部が帰る |

モードごとの違い：

| モード | 違い |
| --- | --- |
| 1 人用 | 両方のスタンドが P1 の手応えで動く |
| 2 人用（オンラインを含む） | 右スタンドは P1、左スタンドは P2 の手応えで動く。オンラインでも、観客は各自の画面だけで動かす（同期しない） |
| 協力 | 2 人の手応えの平均で動く。負けた側の退場はなく、全滅のときだけ帰る |
| エンドレス | 欲求が何度も回り、客入りが波のように変わる。コースが伸びて新しいブロックができると、空のブロックへ客が流れ込む |
| 練習 | シムを止める（今の満席のまま） |

## 売り子

- 左右のスタンドに片側 1〜3 人（画質による）。前の通路と通路の階段を回る。動きと小道具は、ゴール観客席の売り子と同じ `SPEC_VendorWalk` / `SPEC_VendorCall` と樽（`GSP_Keg`）を使う。
- お腹がすいた客は、近くに売り子がいれば手を挙げる（台本の役 `SPEC_RaiseHand`）。売り子は、一番近くで手を挙げている客の列の端（階段のその段）まで来て呼び込む。
- 商品は**列の端から客まで、隣の客から隣の客への手渡し**（`SPEC_PassItemL/R`）で届き、お金が逆向きに戻る。受け取った客は、しばらく「食べる客」（ポップコーンかホットドッグ）になる。
- 売り子がいないブロックの客は売店へ歩いて行く。

## 描画のしくみ

### 座った客

- 各ブロックのバッチは席数ぶんの枠を取り、**来ている客を前に詰めて `visible_instance_count` の分だけ描く**。客が帰ったら最後の客と入れ替えて、数を 1 減らす。隠した客の頂点までシェーダーが処理しないようにするため。
- 小道具を持つかどうかで 2 つのバッチに分かれているので、食べる客になるときは「小道具あり」のバッチへ移す。どちらのバッチも席数ぶんの枠を取る。
- 席とバッチの中の番号の対応は `CrowdSim` が持つ。
- **台本の役**：シェーダーの役に「台本」を足し、立つ・座る・手を挙げる・手渡す・受け取るを、指定した時刻から 1 回だけ再生する。
  動きの番号は `habit` に 512 × 動きの番号として足し、開始時刻は `INSTANCE_CUSTOM.x` に入れる。時刻は、毎フレーム渡す共通の時計 `sim_clock` で測る。台本の動きはウェーブや合図より優先する。

### 歩く客

- 片側 1 つの MultiMesh（小道具ありのメッシュと同じマテリアル）を使い、CPU が毎フレーム位置と向きを動かす。
- 歩く動きは、脚を座った形にしない焼き込みにする。`SeatedSpectatorKit` に、腰と脚を座面へ合わせない焼き方を足す。今の動きは 32 本で上限（`MAX_CLIPS`、シェーダーの `clips[40]`）は 40 なので、どちらも 56 に上げる。
- 席を立つ流れ：座った客が台本の「立つ」を再生し、立ち終わった時点で座った客を消して、同じ見た目の歩く客を出す。戻るときはこの逆。
- 歩く客は合図に反応しない。ウェーブの途中に空いた席はそのまま穴になる（本物らしい）。

### 新しい動き（ライブの Blender、`assets/goal_stand/source/goal_stand_crowd.blend`。段階3で作った）

| 動き | 元 | 焼き方 | 使う場面 |
| --- | --- | --- | --- |
| `SPEC_Walk` / `SPEC_Run` | UAL `Walk_Loop` / `Jog_Fwd_Loop` | 脚は自由 | 歩く・ゴール競争で急いで戻る |
| 階段 | （`SPEC_Walk` で代用） | | 段の高さに合わせて足元が上下する。見た目で困らないので専用の動きは作らない |
| `SPEC_StandIdle` / `SPEC_StandPhone` | 既存の `SPEC_FoldArms` / `SPEC_Phone` | 脚は自由 | 行列で待つ。ゴール観客席は立ち見なので、元の動きがもともと立った姿勢 |

## 見え方と負荷

- プレイ中のカメラ（三人称、画角 50°）からは、スタンドはカメラから約 30 m より先が、画面の端に小さく映る。細かい演技より**人の流れの量**が目立つので、歩く客はカメラの前方 30〜120 m のブロックの、前の通路と階段に優先して出す。
- 後方通路は、コースから見ると最上段の客の頭越しに上半身が見える高さにある（計算上。実画面で確かめる）。行列と通り抜ける客はここで見せる。
- 見えないブロック（カメラの視錐台の外か、遠いブロック）では歩かせない。歩く客が画面の外へ出たら、行き先へ瞬間移動して用事を済ませてよい。
- 更新の頻度：欲求と客入りは 0.25 秒おきに、ブロックを順に少しずつ更新する。毎フレーム動かすのは、歩く客と台本の役だけ。

| 画質 | 歩く客（片側の同時人数） | 売り子（片側） |
| --- | --- | --- |
| low（モバイルを含む） | 12 | 1 |
| balanced | 24 | 2 |
| high | 40 | 3 |
| ultra | 48 | 3 |

目標は、シム全体で 1 フレーム平均 0.3 ms 以内（balanced）。比べる値として、ゴール観客席の更新は 1 フレーム平均 0.81 ms（docs/crowd_extras.md の計測）。

## 今の演出との関係

- ウェーブ・応援の拍・驚き・勝者のダンス：座っている客だけが参加する。台本の動きの最中の客と歩く客は参加しない。
- 居眠り・食べる客：固定の役から、欲求で移り変わる役にする（退屈すると居眠り、買ったら食べる）。
- マスコット・応援団長・ペア：固定のまま、帰らない。
- ゴール観客席：特等席として満席のまま（帰らない）。売り子は今のまま。
- サントリーニのテラス席（`santorini_terrace_stand.gd`）：シムは止める（今のまま）。歩く道の JSON を作れば、後から入れられる。
- 試合の記録・ハイライトの再生：観客の状態は記録しない。再生中は、その時点のシムで動く。
- PV 撮影・今のテスト：`stage_environment` の設定でシムを止められるようにする。止めたときは今と同じ結果になる。

## 段階4の実装（2026-10-29）

### 試合の終わり（`CrowdMood`）

- `finished`：判定の演出・結果画面・ゲームオーバー（`RESULT_CEREMONY` / `CLEAR` / `GAME_OVER`）。見どころは 0.9 に保ち、

  - 1 人用・協力・エンドレスのゲームオーバー：4 秒後から全体の一部（0）。クリアなら誰も帰らない。

| クリア | 誰も帰らない |

- 試合後の帰る速さは 1 秒に 8 人（試合中は 4 人）、下限は 2 割（試合中は 3 割）。連れは一緒に帰る。
- 脱落などで自分の選手の手応えが 0.35 より低いファンは、試合中に帰ったら戻らない（ゴール競争で脱落した選手のファンが戻る不自然さをなくした）。
- エンドレスでコースが伸びて足されたブロックは、応援団長とペア（帰らない固定の役）だけが座った状態で開き、ほかの客の 9 割が 5〜90 秒で流れ込む。
  `GrandstandCrowd` は足したブロックの客を、シムで座っている人だけ描く（前は最初の 1 フレームだけ全員が見えた）。

### 台本の試合で測った客入り（`crowd_sim_unit` の `_check_matches()`）

両方のスタンド（右は P1、左は P2 のファンが 55%、相手のファン 12%、ほかは中立）に、15 秒おきの問題・失敗・HP・脱落・ゴール競争・判定を流した。

| 試合 | 右（P1 側）／左（P2 側）の入り |
| --- | --- |
| 接戦の 2 人用（P1 の勝ち） | 開始 0.67 → 130 秒で 0.97、ゴール競争で 1.00。判定後、左は 0.59、右は 0.81（右の P2 ファンと中立の一部が帰る） |
| 片方が崩れる 2 人用（P2 が 70 秒で脱落） | 左が 0.78 → 0.54 へ減っていく。ゴール競争で 0.64（中立とまだ来ていなかった客）、判定後 0.53 |

### 検証（2026-10-29）

- `crowd_sim_unit`（141 項目すべて成功）：上の 5 試合、新しいブロックが 130 秒で 88% まで埋まる、ほかは段階3と同じ。2 スタンドで 1 フレーム平均 0.31 ms。
- `crowd_sim_runtime`（成功）：本物のスタンドを試合中に 1 ブロック伸ばすと、最初は固定の役の 15 人だけが描かれ、120 秒後に 84 人。`update_sim()` は平均 0.45 ms。
- `crowd_cues_gameplay`（本物の `game_world.tscn`）は成功。

### 残っていること（段階4の時点）

- 本物の試合（問題が出る試合）を最後まで通して流すテストはまだない（テストの環境では問題が出ず、約 10 秒でゲームオーバーになる）。判定後の退場は台本の試合でしか確かめていない。
- `update_sim()` の最悪の 1 フレームが、まれに 4〜6 ms になる（描画ありの試験、2 万フレームに数回）。原因はまだ調べていない。

## 段階5の実装（2026-10-29）

左右のスタンドにビールの売り子を出し、手を挙げた客へ列の端から手渡しで届くようにした。

### 売り子（`CrowdSim` の `Vendor`）

| 状態 | すること |
| --- | --- |
| 呼び込み・巡回 | 自分の受け持ち（スタンドを人数で均等に分けた範囲）の前の通路を、通路から通路へ歩き、止まるたびに 2〜4 秒呼び込む（`SPEC_VendorWalk` 0.85 m/s / `SPEC_VendorCall`） |
| 列へ | 受け持ちの中で一番近い、まだ誰も向かっていない挙手へ。前の通路から通路の階段を、その段の高さまで上る（列の側へ 0.55 m） |
| 手渡し | 列のほうを向いて `SPEC_VendorHand`。カップは列の端の客から隣へ隣へ（`SPEC_PassItemL/R`、座った客の左＝スタンドの +Z）、0.6 秒おきに客まで届き、客がお金を返すと同じ道を戻る。空席は飛ばす。カップを渡している人の手にはカップが見える |
| お礼・戻る | 1.5 秒呼び込んでから、前の通路へ下りる |

- 人数（片側）：low・モバイル 1、balanced 2、high・ultra 3（`StageEnvironment.crowd_vendors()`）。見た目は黄色い服・帽子・樽とカップ。
- 小道具：`SeatedSpectatorKit.PROPS` に「樽＋カップ」（売り子、9）と「カップ」（客、10）を足した（"A+B" で 1 つの小道具に複数のメッシュ）。売り子の動き `SPEC_VendorWalk` / `SPEC_VendorCall` も脚が自由な焼き込みで足した（45 本）。
- 描画：売り子は歩く客と同じバッチ（`Walkers`）の後ろに描く。
- 受け持ちは見えているスタンドの中だけ。ゴール観客席のモニターでスタンドを切る（`AiquizStadiumStand.fit_end()`）と、その先のブロックは隠れて海になるので、
  `fit_end()` が見えている長さを `GrandstandCrowd.set_walk_z()` → `CrowdSim.set_walk_z()` で渡し、受け持ちをその中で分け直す。外に残った売り子は客をあきらめ、受け持ちの一番近い所から呼び込み直す。
  確かめ方：`tests/crowd_vendor_bounds_bootstrap.gd`（`--headless`、スタンドを z=95 で切って 240 秒回し、売り子が端を越えないこと）。

### 客

- お腹がすいた客は、カメラに映っていて、そこを受け持つ売り子がいれば、7 割が手を挙げる（`SPEC_RaiseHand`）。残りは売店へ歩く。
- 45 秒待っても売り子が来なければ、手を下ろして売店へ歩く。ゴールへの競争・試合の終わりでも手を下ろす。
- カメラが外れたら、売り子が見えない所で渡したことにする（向かっている途中の売り子は前の通路へ戻る。手渡しが始まっていればそのまま終える）。
- 届いたら手を下ろし、カップを持って飲む（「食べる客」と同じ動き）。

### 検証（2026-10-29）

- `crowd_sim_unit`（155 項目すべて成功）：売り子 2 人、挙手→列へ→手渡し→戻る、カップの順番（座っている 3 人→客→お金を戻す 3 人）と、
  渡す人の手のカップ、通路と前の通路から外れない、ゴール競争で手を下ろす、カメラが外れたら渡したことになる、
  自然に空腹になった客が呼ぶ（3 ブロックを映して 4 分で 37 回呼び、11 回届く。残りは 45 秒待って売店へ）。1 フレーム平均 0.32 ms（変わらず）。
- `crowd_sim_runtime`（成功）：本物のスタンドで手を挙げた客に売り子が 16〜30 秒で届け、手渡しを撮影（`12_vendor`）。売店と一人の客を追う試験は、その間だけ全員が売店へ歩く設定（`call_share = 0`）。
- 今のテスト：`side_stand_blocks`、`goal_stand`（790 項目）、`crowd_extras`、`crowd_cues_gameplay`、スカイゲートの通し（`skygate_runtime` p1、ボートの観客も同じキット）は成功。

### 残っていること（段階5の時点）

- 売り子は歩く客とぶつからない判定をしていない（同じ通路の階段では重なることがある）。
- 呼んでも 45 秒以内に届かない客が多い（売り子が遠いとき）。売り子を映っているブロックへ寄せるかは、実際に遊んで決める。

## 検証

- 単体（headless）：決まった種と出来事の並びで、次を確かめる。入りが 60〜70 % から始まる。接戦で増える。中だるみと大差で下限 30 % まで減る。ゴールへの競争では帰る客が出ず、歩く客が席へ戻る。判定後は負けた側から帰る。
- 実行（描画あり）：カメラを 1 ブロックに向けて決まった流れを再生し、階段を上り下りする客、窓口の行列、売り子の手渡し、判定後の退場を撮る（`artifacts/crowd_sim/`）。シムにかかる 1 フレームの時間を測る。
- 実ゲーム：`game_world.tscn` で、シグナルから見どころと手応えが動くこと、プレイ中の画面の端で人の流れが見えることを撮る。
- 今のテスト（`crowd_extras`、`side_stand_blocks`、`crowd_cues_gameplay`、`result_ceremony`、PV 撮影）が、シムを止めた状態で今まで通り通ること。

## 未決・リスク

- 後方通路を広げた分は、水上飛行機・ヘリの開始位置とは干渉しない（段階2で確認）。背景や PV の画角との兼ね合いは、実際の場面で見る。
- 後方通路の客は、引きの画面と見下ろしでは見える（段階2の撮影）。プレイ中のコースのカメラからは、売店の窓がわずかにのぞく程度。
- 列を横に通るとき、座っている客の膝と重なる。遠目では気にならない見込みだが、近い引きの場面で目立つなら、通られる客が膝を引く台本を足す。
- 帰る客を「しっかり」出すと、プレイ中のスタンドが寂しく見える場面がある。下限 30 % と戻る客の量は、実際に遊んで調整する。
- 2 人用のオンラインでは、2 人の画面で観客の動きが違う（同期しない）。
